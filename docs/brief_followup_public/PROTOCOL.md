# 후속 답변 길이 실험 — 사전 고정 기준

2026-10-14. 기존 공개200건 원본은 변경하지 않는다. 분석은 historical_analysis.json에 원본 SHA256과 함께 남긴다.

## 가설과 범위

모델 처리 중앙값2596.38ms/p954378.37ms, 출력 토큰 중앙값109.5/p95362. 출력 토큰과 모델 시간 Pearson r=0.456. 기록0인 deleted/prior_day_only에서 긴 출력이 나타난다. 그러나 최장17.14초 모델 요청은99출력 토큰이라 길이가 모든 지연의 원인은 아니다. 역사적 계측은 SDK·네트워크·공급자·추론·생성을 분리하지 못한다.

검증된 읽기 전용 후속 코칭에만 **답변250자 이내, 결론과1~2실천 문장, 요청한 최신 수치와 안전 안내 유지**를 추가한다. 기존 긴 프롬프트·도구·모델·low추론·전달 방식·읽기·저장pipeline을 유지한다. 기존 compact prompt 실험과 다르며 그 실패 결과를 지우지 않는다. 하드 토큰 상한/답변 사후 절단/요청 간 캐시 없음. 첫 추천·불확실하거나 변경을 요구하는 요청에는 적용하지 않는다.

Google 공식 문서상3.8flash의 지원 추론 수준은low/medium/high이며 이미low다. max_output_tokens는생각 토큰도 포함해 낮은 제한은 미완성/빈 답변을 만들 수 있다: https://ai.google.dev/gemini-api/docs/thinking . 응답 길이는 프롬프트로 유도하고 미완성 답변을 자르지 않는다.

## 동일 조건 공개 비교

- 동일 runtime 커밋에서 BRIEF_FOLLOWUP_ANSWER false→true만 전환. BUDGET_PIPELINE=true 양쪽 유지. 동일3.8flash/low/invoke와 기존후속프롬프트, 기존 재시도·예산 제한 유지.
- 기존 네 질문×다섯 실제DB상태×다섯반복=전후100시도 각각. 동일 계정·순서·질문·최신 섭취/목표·오래된대화 사용. frozen dataset hash를비교한다.
- 순차 시간대 비교. 준비/조회는계측밖, 준비요청은별도 파일. 각 응답build/answer_style/예산계측확인. 정식100건 실패·timeout·blocked는삭제/교체하지 않는다.
- 실패포함전체시도중앙값/p95, 성공응답중앙값/p95, 첫표시, 모델시간, 토큰, 실패율·외부오류, 최신수치·미저장, 같은blindGemini judge5기준 기록.

## 채택 기준 — 측정 후 변경하지 않음

1. 양쪽100시도완료/최신값/미저장, proposal0, 정확한build/스타일/finite시간.
2. 실패포함전체시간 중앙값≥5%감소, p95비악화(후보≤기존).
