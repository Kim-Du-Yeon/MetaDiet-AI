# 일반 음식 기본 분량과 직접 계산 카드 (2026-10-15)

## 문제와 원인

김치찌개·간장불고기가 대표 음식 설정에 없어 간단 입력 파서가 전체 요청을 처리하지 못했다. 이후 제품 검색 경로가 제조사 후보와 빈 g 입력을 표시했다. 사용자가 이미 입력한 200g도 그 화면에서 다시 요구할 수 있었다.

## 변경

- 김치찌개·간장불고기(띄어쓰기 별칭 포함)는 기본 200g/1인분으로 계산 카드에 바로 표시한다. 명시한 g와 인분 수를 우선하며 추가 조리법·제조사 질문을 하지 않는다.
- 간장불고기는 기존 CSV의 익힌 소불고기 대표 기준을 사용한다. 실제 고기 종류·양념과 차이가 있으므로 대략값으로 표시한다.
- CSV에 없는 김치찌개는 식약처 코드 `P123-208020300-0054`의 검토된 스냅샷을 고정했다. 임의 첫 검색 결과나 모델 생성 영양값을 사용하지 않는다. 100g당 49kcal/탄수화물5.27g/단백질4.12g/지방1.24g이며 원본 날짜는 2026-06-18이다.
- 이 스냅샷은 **제품 유래 대표값**이다. 전국 음식의 평균이나 실제 먹은 브랜드의 정확한 값이라고 주장하지 않는다. 제조사 `(주)푸르샨식품`, 기준량, 출처 URL, 검토 버전을 보존한다. 앱 기본 200g도 실측 표준을 뜻하지 않는다.
- 기본 분량은 `200g (1인분)`으로 표시한다. 명시한 g는 중복 표시하지 않는다. 수량 수정·서버 재계산·제외·전체 취소·확정 전 미저장 정책을 유지한다.

## 검증

- 사용자 예시, 분량 생략, 350g/150g, 2인분, 띄어쓰기, 기본값 표시를 회귀 테스트에 추가했다.
- Agent 통합 경로에서 제품 선택 카드가 없고 모델 호출 없이 pending proposal만 생성함을 확인했다. 김치찌개 g 수정과 불고기 인분 수정도 서버 재계산 테스트에 포함했다.
- 백엔드 전체: **1057 passed, 기존 1 skipped**. 프론트 전체: **23 suites / 77 passed**, production build 성공.
- 초기 테스트는 파서 미지원으로 실패했고 수정 후 통과했다. 추가 테스트의 `portion` 경로 오류는 실제 계약인 `nutrition_metadata.portion`에 맞춰 수정했다. 테스트를 제거하거나 새로 skip하지 않았다.
- 기능 회귀 검증이며 속도·정확도 전후 비교가 아니다. 실사용 성공률·성능 개선 수치를 주장하지 않는다.

## 후속 실제 브라우저 검증

사용자 로그인 후 입력·기본값·수정·제외·취소·확정·대기/확정 후 새로고침과 캘린더 확인을 완료했다. [단계별 결과·캡처·발견한 표시 오류 수정](default-serving-browser/README.md). 아래 최초 배포 시의 로그인 미검증 한계는 이 후속 검증으로 보완했다.

## 한계

대표 기준이 없는 음식은 기존 기입·제외·취소 흐름을 사용한다. 이번 변경으로 모든 미등록 음식의 영양값을 생성하지 않는다. 별도 정확한 제품 찾기 기능은 유지한다.

## 공개 배포 확인

- main `0f87f1700dc6a9a2d0b3aeaffe4f8d624f70fb41` 푸시 후 Render Auto-Deploy / Live를 확인했다. API health 및 웹 build-info가 같은 커밋을 반환했다.
- 별도 임시 계정의 공개 API에서 명시한 200g 보존·기본 200g/1인분·제조사 선택 없음·확정 전 미저장·취소·pending 복원을 확인했다.
- 김치찌개350g/불고기2인분400g으로 수정하고 밥을 제외했다. 김치찌개는 서버에서171.5kcal로 재계산됐고, 확정을 두 번 요청해도 실제 기록은2행만 저장됐다. 확정 후 복원에서 pending이 사라졌다. 임시 계정과 데이터는 계정 삭제 endpoint로 정리했다. [비식별 기능 검증 결과](default-serving-public.json).
- 웹의 배포 번들 `main.e3d10c55.js`에 `(1인분)` 문구가 포함됐다. 실제 번들의 유니코드 escape를 고려해 검증했다. 최초 확인 명령의 PowerShell 인용 오류는 [공식 here-string 규칙](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_quoting_rules)으로 수정했다.
- 브라우저는 로그아웃 상태였다. 따라서 이번 공개 검증은 **API 흐름 및 배포 번들 확인**이며 로그인 후 브라우저 전체 조작을 완료했다고 주장하지 않는다. 카드 렌더링·수정·제외는 프론트 회귀 테스트로 확인했다.
