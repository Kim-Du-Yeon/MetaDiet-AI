# 파서·청킹 3×3 실행 파일럿

동일 코퍼스 10개·PDF 24페이지. 최종 품질/최적 구성 판정 전 실행 검증 결과다.

| 파서 | 완료 문서 | 텍스트 페이지 | 추출 문자 | 인식 표 블록 | 그림/위치 블록 |
|---|---:|---:|---:|---:|---:|
| pypdf | 10/10 | 24 | 61097 | 0 | 0 |
| pdfplumber | 10/10 | 24 | 60047 | 27 | 13 |
| docling (PDFium) | 10/10 | 24 | 71129 | 6 | 11 |

| 파서 | 청킹 | 검색 청크 | 부모 문맥 |
|---|---|---:|---:|
| pypdf | page | 24 | 0 |
| pypdf | parent_child | 182 | 45 |
| pypdf | section | 62 | 0 |
| pdfplumber | page | 24 | 0 |
| pdfplumber | parent_child | 180 | 44 |
| pdfplumber | section | 62 | 0 |
| docling (PDFium) | page | 24 | 0 |
| docling (PDFium) | parent_child | 212 | 52 |
| docling (PDFium) | section | 95 | 0 |

PyPDF의 표/그림 0은 구조 블록을 식별하지 않는 텍스트 기준선이라는 뜻이다.
PDFPlumber 그림 수는 위치 메타데이터 수이며 이미지 이해/OCR 정확도가 아니다.
파서별 표 감지 기준이 다르므로 개수·문자 수가 많다고 정확도가 높다고 판단하지 않는다.
Docling 기본 백엔드는 KDRI 무기질에서 네이티브 오류가 발생했다. PDFium 별도 레시피는 전체 코퍼스에서 검증했다.

미완료: 검토된 골드, CER/표 셀·수치 정확도, 스캔 OCR, 검색/Ragas 점수, 임베딩·검색 비교, LangSmith 실험.
실행 로그 시간에는 프로세스 시작·모델 준비가 포함되며, 동시 디버깅도 있어 최종 성능 벤치마크로 사용하지 않는다.
전체 원문 비교/24페이지 사람 검토는 완료되지 않았다. 두 페이지의 원본 렌더링만 대조했다.
