# MetaDiet AI 베타 사용 안내와 피드백 수집

공개 베타에서 식사를 간단히 기록하고 다음 식사를 상담하는 방법입니다. 처음에는 소수 사용자에게 공유하고, 사용 중 막히는 부분을 개선하는 데 피드백을 활용합니다.

## 사용자에게 공유할 안내

접속: [MetaDiet AI 공개 베타](https://metadiet-web.onrender.com)

1. 회원가입과 이메일 인증을 완료하고 로그인합니다. 기본 정보와 목표를 설정합니다. 일반 사용자는 관리자 이메일 등록이 필요하지 않습니다.
2. 실제로 먹은 음식을 채팅에 간단히 입력합니다. 예: `오늘 점심에 닭가슴살 밥 한공기 김치 먹었어`.
3. 양을 생략하면 앱의 기본 분량으로 계산합니다. 직접 입력한 g수나 개수는 우선 적용합니다. 카드의 음식과 양을 확인하고, 필요하면 분량을 수정하거나 음식을 제외합니다.
4. 수정했다면 **수정한 분량 다시 계산**을 누릅니다. **이대로 기록**을 눌러야 실제 섭취 기록으로 저장됩니다. 연습 입력은 **취소**합니다.
5. **점심 추천** 또는 **저녁 추천**으로 다음 식사를 상담합니다. 추천받은 식단과 실제 먹은 기록은 구분합니다.
6. **캘린더**에서 날짜별 섭취 기록을 확인합니다. 잘못 저장했다면 해당 기록의 수정·삭제 버튼을 사용합니다. 삭제에는 복구 기능이 없으므로 대상을 먼저 확인합니다.

영양값은 대표 식품과 기본 분량에 따른 대략값이며 실제 제품·재료·크기와 다를 수 있습니다. 정확한 제품 정보를 쓰고 싶을 때만 보조 기능인 **제품을 정확히 입력** 또는 **제품 영양표 입력**을 사용합니다. 기본 기준이 없는 음식은 기입하거나 제외·취소할 수 있습니다.

무료 서버가 쉬고 있었다면 첫 요청에 기동 시간이 필요할 수 있습니다. 화면의 안내를 기다리고, 오류가 표시되면 재시도합니다. 저장 여부가 불분명할 때는 같은 식사를 반복 확정하기 전에 캘린더를 확인합니다.

## 피드백 보내는 방법

**설정 → 베타 피드백**에서 만족도(1~5점)와 피드백 종류를 선택하고 **피드백 보내기**를 누릅니다. 종류는 전반적인 의견·답변 품질·근거와 출처·사용 편의성·오류 신고입니다. 의견은 선택사항이며 최대1000자입니다. 만족도 선택만으로도 제출할 수 있습니다.

불편했던 점 하나만 남겨도 충분합니다. 오류를 재현할 정보가 있다면 의견란에 아래처럼 작성해주세요. 모든 항목을 채울 필요는 없습니다.

> 휴대폰 Chrome / 10월15일 오후2시쯤 / 분량을 바꾸고 다시 계산했는데 버튼이 계속 비활성화됐어요.

대화·식사·인바디 기록은 피드백에 자동 첨부되지 않습니다. 오류와 관련된 입력 내용이나 화면 캡처는 필요한 부분만 선택적으로 공유해주세요. 비밀번호·인증 코드·API 키는 보내지 말고, 캡처의 이메일·신체 정보 등 개인정보는 가려주세요. 인앱 피드백 전송 자체가 실패하면 사용자는 모집 담당자에게 발생 시각과 증상만 전달할 수 있습니다. 담당자는 기존에 안내한 연락 채널을 사용합니다.

## 운영자의 수집과 개선 절차

초기 운영 예시는 3~5명이 며칠 동안 실제 식사를 기록해보는 방식입니다. 이는 모집 규모 제안이며 확보된 사용자 수나 측정 결과가 아닙니다. 가상의 식사를 저장하도록 요구하지 않고, 연습이 필요하면 취소까지 안내합니다. 이 문서는 초대 메시지를 실제로 발송한 기록이 아닙니다.

1. **관찰:** 설정의 관리자 제품 운영 지표에서 활성 사용자·이벤트·실패·지연을 확인하고, 수집된 피드백을 함께 검토합니다. 관리자 접근과 trace 연결은 [관리자 안내](ADMIN_ANALYTICS_GUIDE.md)를 따릅니다. 모든 사용자를 `ADMIN_EMAILS`에 등록하지 않습니다.
2. **분류:** 저장·로그인 차단, 잘못된 기록·계산, 불필요한 질문, 느린 응답, 화면 불편으로 구분합니다. 먼저 기록 유실·중복·소유권 관련 문제를 처리합니다.
3. **재현:** 발생 시각·증상으로 Render 로그와 LangSmith 실행을 찾습니다. 실제 trace ID가 확보된 경우 연결해 확인하고, 모르면 추정 ID를 만들지 않습니다. 오류 로그와 공식 문서를 근거로 수정합니다.
4. **회귀 방지:** 개인정보를 제거한 최소 입력으로 재현 테스트를 만들고, 수정 후 같은 사례와 관련 회귀 검사를 다시 실행합니다. 해결되지 않으면 실패 단계·로그 근거·시도한 조치·필요한 외부 조건을 기록합니다.
5. **결과 기록:** 사례별 상태를 접수→재현→수정→재검증으로 관리합니다. 사용자 원문·개인정보를 공개 저장소에 복사하지 않고, 비식별 요약과 검증 근거만 포트폴리오에 반영합니다.

피드백 종류·접수 날짜·비식별 증상·재현 조건·관련 이슈·처리 상태를 운영 기록의 기본 항목으로 사용합니다. 제품 이벤트 수집만으로 답변 정확도나 실제 건강 효과가 자동 검증되는 것은 아닙니다.

현재 관리자 화면은 운영 지표를 보여주며 **개별 피드백 의견을 열람하는 목록 화면은 없습니다**. 인앱 의견은 서버에 저장되므로 운영자 권한으로 별도 조회해 검토해야 합니다. 모집 담당자에게 직접 전달된 의견과 구분하고, 원문을 공개 저장소나 분석 로그에 옮기지 않습니다. 전용 피드백 관리 화면은 후속 개선 항목입니다.

소수 베타에서는 사용자 수·피드백 건수·재현된 오류와 해결 건수를 표본 수와 함께 기록합니다. 만족도 응답자는 전체 사용자와 구분합니다. 속도·정확도 개선을 주장하는 비교는 같은 고정 사례로 **조건별 최소100회** 수행하고 실패·타임아웃을 분모에 포함합니다. 합성 평가와 실제 사용자 결과를 섞지 않습니다.

## 개발 검증 기록 정리

2026-10-15 사용자의 삭제 요청과 대상 확인 후, 같은 날 아침에 검증 목적으로 저장했던 **김치찌개300g·소불고기400g 두 건만 삭제**했습니다. 새로고침 후 해당 날짜의 두 기록이 사라진 것을 확인했고, 기존 다른 날짜의 실제 섭취 기록은 수정하거나 삭제하지 않았습니다. 이 두 건을 실제 사용자 섭취 사례로 보고하지 않습니다. 대화와 검증 문서의 과거 확정 이력은 삭제하지 않았습니다. 다른 이벤트도 삭제하지 않았으므로 제품 지표에서 검증 활동까지 자동 제외됐다는 의미는 아닙니다.

검증 당시의 캡처와 수정 과정은 [실제 브라우저 검증 보고서](default-serving-browser/README.md)에 남아 있습니다. 캡처는 당시 상태를 보여주는 증빙이며 현재 계정에 해당 두 기록이 남아 있다는 뜻이 아닙니다.
