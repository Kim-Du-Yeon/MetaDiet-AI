**구현·개발셋 검증은 완료했지만 본 비교는 HTTP402 선불 크레딧 소진으로 판정 보류다.** 조건별100시도 원본은 남았으나 요청 완료는53/54건이고, 최종 Pro 평가·전체 비용 검증을 완료하지 못했다. 운영OFF·미배포이며 브라우저 기능 검증도 진행하지 않았다.

별도 개발의 한 문항은 충분한 이웃 문단을 찾고도 일반인 조건을 추가해 한 번 더 검색했다. 최종 답은 정확했지만 불필요한 재검색 가능성은 남아 있다. 합성20문항 성적을 실제 사용자 정확도나 임상 검증으로 일반화하지 않는다.

## 변경과 원인

이전 [핵심 수치·적용 범위 비교](../20261021-core-scope/README.md)에서 핵심 수치 누락을 감지해 재검색했지만 같은 페이지의 다른 청크만 회수해3건을 보류했다. 한국어 표 질문2건도 불필요하게 보류했다. [과거 실패의 문맥 구성 진단](adjacency-diagnostic.json)은 누락된 문장이 바로 다음 청크에 있었음을 확인한 기능 점검이며 새 품질 성적이 아니다.

후보는 점수를 통과한 원문 청크와 정확히 일치하는 로컬 빌드 anchor를 찾고, 같은 문서 SHA·파일·페이지±1 안의 바로 이전/다음 청크만 추가 평가 후보로 사용한다. 새 원격 검색·임베딩·토크나이저 모델 호출은 없다. 최대2개 이웃의 연속700자 구간을 질문 키워드 커버리지로 선택하고 원문 해시·시작/끝 위치를 보존한다. 이웃을 추가한 전체 문맥은 모델의 충분성 평가를 거친다. 개별 문서의 관련성을 모두 보장하는 필터는 아니다. 최초 근거 우선·전체8문서/6000자·2회 검색/평가·기본35초 제한은 유지한다.

로컬 캐시는 설정한 활성 빌드의 namespace·임베딩 모델/차원을 확인하고 artifact hash가 제공되면 검증한다.16MiB/10000청크 상한, 단일 캐시와 초기화 잠금으로 동시 첫 요청의 중복 역직렬화를 막는다. Kiwi/BM25를 로드하지 않는다. 빌드 오류는 원래 근거 평가로 복귀하지만 진단을 남기며 본 비교의 운영 실패율에 포함한다. 이는 장시간 메모리 안정성 검증을 대신하지 않는다.

한국어 답변 안내는 표의 항목별 머리글이 명시하는 지표 구분과 의미를 알 수 없는 빈 셀을 구분한다. 빈 셀만으로 임상·규제상 미적용을 단정하지 않는다. 컨트롤러는 ‘불완전한 자료에서 무엇을 단정할 수 있는가’ 질문에는 한계를 답할 수 있도록 하고, 사용자가 묻지 않은 일반인/비참여자 조건을 만들어 보류하지 않게 한다. 실제 영양 수치나 주 비교 골드 답을 프롬프트에 넣지 않았다.

## 별도 개발

기존 합성12개와 새 인접 청크·표 해석8개를 더한20개다. 모든 값·문서·표는 가상이며 실제40문항·사용자 기록과 구분한다. 네 실행의 질문/골드는 동일하다. 초기 실행과 [v2](development-v2/cases.json), [v3](development-v3/cases.json)의 실패를 보존하고 [v4](development-v4/cases.json)에서 최종 후보를 확인한다. 기대 검색 횟수와 최종 근거 판단을 따로 집계하고, 답변 품질은 별도 Pro 평가로 확인한다. 개발 생성 비용 전체와100쌍 serving 비용을 혼합하지 않는다.

## 장애 후 보완과 재개 조건

기존 runner는402 이후에도 대기 사례를 실행했다. 원본의1건은 credits로 분류됐으나92건은 `KeyError`로 남았다. 검색 자체가 예외를 내면 결과에 max_score가 없고 QA가 이를 다시 읽으며 원인을 가리는 계약 버그를 오프라인에서 재현했다. 동시 로그의 반복402와 이 버그를 확인했지만, 원래 제공자 상태를 잃은92행을 각각 입증된402로 소급 변경하지 않았다.

후속 `adjacent-table-v11-safe-errors`는 기본 점수·안전한 보류 결과와 정제된 제공자 오류 이유를 반환한다. runner는 모델/임베딩의 원인을 보존하고 생성·inline 평가 중 크레딧/인증/일일 한도 오류가 나면 대기 작업을 중단한다. 미시작 슬롯은 실패 시도로 꾸미지 않고 별도 기록하며 exit2를 반환한다. 제공자 오류가 있으면 비용 완료로 표시하지 않는다. 모킹한100쌍 실행에서 생성/평가 각각 첫402 후 실제 호출이3회 이하로 멈추는 테스트를 통과했다. 이는 유료 재실측이 아니다.

[원래 실측 v10 소스](candidate-frozen.py.txt)·[원래 runner](benchmark-frozen.py.txt)·[후속 v11 소스](candidate-after-error-fix.py.txt)·[후속 runner](benchmark-after-error-fix.py.txt)·[후속 해시](postfix-identity.json)를 구분한다. 원래 protocol을 새 코드에 재사용하면 해시 불일치로 중단된다. 현재 수정의 전체 회귀 결과는 validation.json에 기록한다. 기존 skip은 유지하며 테스트를 삭제하지 않았다.

이 실험 폴더는 `.gitattributes`로 줄바꿈 자동 변환을 막아 원본과 해시를 보존한다. 소스 해시는 당시 Windows 작업 파일의 바이트 기준이며 다른 플랫폼에서 새 실험을 할 때는 소스와 프로토콜을 함께 새로 동결해야 한다.

[공식 결제 안내](https://ai.google.dev/gemini-api/docs/billing#verify-billing-status)는 유료 Tier도 양의 선불 잔액을 요구하며, [오류 안내](https://ai.google.dev/gemini-api/docs/troubleshooting)는402를 재시도하지 않도록 명시한다. Tier나 모델만 바꿔 이 문제를 해결했다고 보지 않는다. 사용자는 충전/검증 키 반영 후 알리기로 했으며, 이후 추가 유료 호출은 하지 않았다.

재개 시 비용 상한과 예상 호출량을 먼저 정한다. 실패 사례만 소규모로 확인하고 저장된 답변의 재채점에는 재생성을 하지 않는다. 준비된 최종 후보만 새 폴더에서100쌍을 한 번 비교하며, 크레딧 소진 원본의 실패를 지우거나 성공만 합쳐 통과시키지 않는다. 동일 개발셋 전체의 반복 재생성은 기본 절차로 사용하지 않는다. 청구서 전체 지출은 이 로그로 확정할 수 없다.

실험별 달러 예산의 자동 예약/차단 기능은 아직 구현하지 않았다. 현재 자동 중단은 제공자의 크레딧·인증·일일 한도 오류에 대한 것이다. 다음 대규모 유료 실행은 비용 상한과 차단 방법을 확정하기 전에는 시작하지 않는다.

운영 데이터·환경변수·DB·인덱스는 변경하지 않았다. 자동 배포를 생략한 연구 기록으로 GitHub에 남기며, 배포·실제 브라우저 기능 검증은 조건 통과 후의 미완료 단계다. 이번 `/health` 읽기 확인도30초 타임아웃이어서 공개 정상 상태를 주장하지 않는다.
