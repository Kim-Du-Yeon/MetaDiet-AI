# 실제 분할 Batch·정산 및 동일100 비교 — 배포 기준 미통과

2026-10-21. **분할 Batch 제출·사용량 정산은 실제로 검증 완료했다. RAG 개선안은 품질 게이트를 통과하지 못해 배포하지 않았다.**
추가 유료 재실험은 진행하지 않는다. 운영 사용자 DB·기록·RAG 인덱스를 변경하지 않았다.

## 실제 Batch 검증

- 이전 부분 실행의 저장 답변 14건을 **10건 + 4건**으로 채점했다. 답변 재생성 없음.
- 첫 10건: **예약 $0.215310 → 사용량 정산 $0.030636**, 미사용 예약 **$0.184674 해제**.
- 같은 완료 작업을 실제 API로 다시 수집해 정산액이 중복 반영되지 않음을 확인했다.
- 저장 답변 14건의 총 평가비는 $0.042311. 기존·개선 각각 7/7 정답·충실도 통과지만,
  이는 소규모 부가 확인이며 새로운100건 비교의 분모에 합치지 않았다.
- 본 비교는 완료된 고정 사례 순서대로 paired Pro Batch로 채점했다. 각 요청에 답변 A/B와
  각자의 근거를 제공하며 루브릭·출력2,048·thinking LOW는 유지했다.
- 본 비교의 실제 분할 크기: **10 / 10 / 27 / 3 / 23 / 7 / 15 / 5쌍**.
  최초 최대10개 계획 이후 대기/제출 오버헤드를 줄이기 위해 미제출 사례만 최대30개로 묶었다.
  변경은 해당 제출 전에 `incremental-judge-plan-v2.json`에 기록했다. 질문·골드·답변·문맥·
  모델·루브릭은 변경하지 않았고 품질 결과에 따라 사례를 선택하지 않았다.
- 실제로 최대30개 묶음이 잔여 예산에 따라 27+3, 23+7 등으로 자동 분할됐다.
- **총 Batch job 10개, 내부 추론 요청114개**, 평가된 답변214개(저장14 + 본 비교200).
  본 비교의 paired100 요청 비용은 $0.616398이며 조건별로 절반씩 배분한 값은 개별 청구액이 아니다.
- 모든 job의 원시 사용량을 받아 정산 완료. 한 번에 미완료 Batch는 하나만 유지했다.
- 재구성한 채점 단계의 최대 `기존 지출 + 진행 중 예약`은 **$0.997830**으로 $1 이내였다.
- 장부의 Pro 누적 $0.658710과 원시 계산 합계의 미세 차이는 호출별 마이크로달러 올림 때문이다.
- API 오류/사용량 누락/불명확한 제출 같은 실패 경로는 이번 실측에서 유발하지 않았다.
  해당 경로의 차단·보존은 기존 오프라인 테스트로 확인한 범위다.

## 로그에서 확인한 남은 문제

개선안 오답17건 중 **12건이 표준 '근거 없음' 보류 문구**였다. 일부 추가 보류도 있었다.
고정된 질문/골드/문맥과 Pro 사유만 분석했으며 재채점하거나 판정 기준을 바꾸지 않았다.

- 답할 수 있는 정의·일반 권고까지 보류: 에너지 평형 정의, 1회 단백질 권고 등.
  일부 `round_limit` 경로에서 `retained_initial_documents=0`이 관찰됐다.
  controller는 `sufficient`라 판단했지만 QA가 근거 없음으로 답한 사례도 있었다.
- 필수 조건 누락: 계산식 유지 여부와 새 기준 체위 반영을 함께 묻는 질문에서 한 부분만 답함.
- 의미 방향 오류: `at least`와 `up to`의 경계를 뒤집은 답변이 있었음.
- 답변 잘림: Pro가 문장 끝이 끊긴 응답을 오답/비충실로 판정했다. 한 사례의 출력은
  2,044토큰으로2,048 한도에 가까웠다. 원시 finish_reason은 저장되지 않아 MAX_TOKENS를
  확정 원인으로 단정하지 않는다. 응답 완전성 검출·길이 제어는 후속 개선 과제다.

따라서 '인접 청크가 더 있으면 품질이 자동으로 좋아진다'고 결론내릴 수 없다. 초기 유효 근거 보존,
정의/표/수치 질문별 충분성 평가, 불필요한 보류, 조건·범위 의미 보존이 먼저 개선돼야 한다.
다음 변경은 별도 개발셋의 실패 사례와 오프라인 검사부터 수행해야 하며 이번 데이터에 맞춰
프롬프트를 바꾸거나 동일200건을 자동 재실행하지 않는다.

## 한계·재현 자료

- 100시도는40개 개발 질문의 반복이며 독립 사용자100명이 아니다. 봉인된 최종20문항은 사용하지 않았다.
- Pro 고정 루브릭 자동 평가이며 Ragas/블라인드 사람 검증이 아니다.
- 지연은 로컬 RAG 경계의 검색/생성 시간이다. 브라우저·인증·사용자DB·공개 서버 콜드스타트는 제외한다.
- 최신 사용자 기록 반영은 조회하지 않는 경로이므로 해당 없음이며, 최신성100%로 표현하지 않는다.
- 운영 배포·환경변수 변경·공개 브라우저 호출 없음. 조건 미통과에 따라 배포 단계로 진행하지 않았다.
- 관련 오프라인 회귀91개 재통과. 실제 부하/장애 테스트를 추가 수행했다는 뜻은 아니다.
