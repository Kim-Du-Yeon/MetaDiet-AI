# 분할 Batch 제출과 사용량 정산 — 오프라인 검증

2026-10-21. 실제 생성·채점·임베딩·Batch 제출 없음. 기존 실제 장부의 사용·예약액
$0.099494와 `Budget exhausted: judge` 중단 상태를 그대로 유지했다.

## 구현과 실행 경계

- 기존 저장 답변에서 채점 요청을 만든다. 답변 생성기를 호출하지 않는다. 유효한 기존
  채점 결과는 `old` 경로에서 제외하며 원본 응답·문맥은 수정하지 않는다.
- 최대 10개씩 분할한다. 잔여 예산이 부족하면 분할 크기를 줄이며 최소 1개도 예약할 수
  없으면 전송 전에 캠페인을 중단한다. 한 번에 미완료 작업은 하나만 유지한다.
- 전체 $5와 기존 단계별 $0.10 / $0.25 / $3 / $1 / $0.15는 변경하지 않는다.
- 제출 전에 분할 전체를 예약하고 예약 ID를 공급자 job ID에 연결한다. SDK 전송이 같은
  예약을 사용하므로 이중 예약하지 않는다. SDK 내부 자동 재시도는 계속 비활성화한다.
- 완료 응답의 키·중복·개수·원시 입력/출력/thinking/캐시 사용량을 검증한다.
  검증된 사용량과 동결 요금으로 비용을 정산한 뒤 미사용 예약액을 해제한다.
  이 비용은 토큰 사용량 기반 추정치이며 공급자 청구서는 아니다.
- SQLite 트랜잭션과 사용량 해시로 정산을 멱등 처리한다. 재시작·동시 재수집도 환급을
  중복 반영하지 않는다. 비용이 예약을 넘거나 이미 정산한 사용량과 충돌하면 중단한다.
- 응답 순서는 키로 복원한다. 사용량 누락/응답 누락/키 중복/손상된 저장 결과에서는
  예약을 해제하지 않고 다음 분할을 보류한다. 나중에 사용량만 확인되면 재채점 없이 정산한다.
- 채점 파싱 실패도 유료 응답이면 비용을 포함한다. 누락 비용을 0으로 간주하지 않는다.
- 제출 결과가 불명확하면 자동 재제출하지 않는다. 중단 뒤 stale lock이나 이름 없는
  제출 기록은 운영자가 확인해야 한다. 이는 중복 청구 방지를 위한 보수적 제한이다.

## CLI 동작

모든 명령은 `--allow-paid`가 없으면 모델 API 실행 전에 중단한다. 이번 검증에서는
해당 옵션으로 실제 실행하지 않았다. 아래는 명령 역할 설명이며 실행 허가가 아니다.

| 동작 | 의미 |
|---|---|
| `old` | 저장된 완료 답변 중 미채점 건으로 캠페인 생성, 최대 한 분할 제출 |
| `pairs` | 완전한 100쌍 검증 후 캠페인 생성, 최대 한 분할 제출 |
| `collect` | 기존 작업 상태·응답 수집/정산만 수행. 다음 작업 제출 없음 |
| `advance` | 기존 작업 수집/정산 후 최대 한 분할 제출 |

`--job`은 캠페인 JSON, `--chunk-size`는 최대 분할 크기(기본 10), `--budget-ledger`는
동일한 예산 장부를 지정한다. 캠페인 `.parts/`에 개별 제출/응답/예약 연결을 저장하고,
전체 완료 후 같은 이름의 `.grades.jsonl`로 합친다. 실패 행도 제거하지 않는다.
입력/모델/요청 설정/장부/분할 크기 해시가 바뀌면 재개를 차단한다.

## 오프라인 확인

- 저장된 실제 답변 14건에서 요청 14개 구성: 재생성·새 채점 없음.
- 모의 작업 100개를 10개씩 처리: 제출 → 대기 → 사용량 정산 → 다음 분할 → 통합 결과 확인.
  이는 기능 시뮬레이션이며 실제 품질·속도·비용 100건 비교가 아니다.
- SDK의 실제 요청 직렬화와 가짜 HTTP 응답으로 예약 1회만 반영되는지 확인.
- 사용량 누락 후 복구, 정산 직전 프로세스 오류, 잘못된 응답 키, 저장 결과 손상,
  입력 변경, 중복 제출 차단, 단순 조회 시 미제출, 동시 정산, 상한 불변 검증.
- 최종 관련 회귀 테스트 **91개 통과**. 기존 실제 예산 장부는 읽기 전용 확인만 했다.
- 최종 전체 백엔드 회귀 **1,566개 통과**, 기존 스킵 1개·기존 경고 3개. 테스트 제거/신규 스킵 없음.

## 한계와 다음 실제 검증

분할은 한 번에 필요한 예약액을 낮추지만 전체 채점 비용이 $1 이내임을 보장하지 않는다.
누적 비용이 한도에 닿으면 나머지 작업을 중단한다. 실제 공급자 Batch의 장시간 대기,
부분 실패·사용량 반환 지연은 아직 검증하지 않았다. 기존 캠페인의 중단 상태를 자동으로
해제하거나 새 장부로 우회하지 않는다. 실제 호출은 별도 요청을 받은 뒤 진행한다.

공식 기준: [Batch API](https://ai.google.dev/gemini-api/docs/batch-api),
[Pro Batch와 캐시 요금](https://ai.google.dev/gemini-api/docs/pricing).
Batch의 일반 입력/출력은 Standard의 50%이며 Pro 캐시 입력은 Standard 단가를 유지하므로
캐시 입력에 50% 할인을 다시 적용하지 않는다.
