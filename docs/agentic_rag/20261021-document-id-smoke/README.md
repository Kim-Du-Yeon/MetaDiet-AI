# 반복 원문 연결 실패 수정: 문서 ID 선택

## 원인과 변경

기존 v12는 모델이 문서를 다시 출력한 발췌와 원문의 일치를 요구했다. ag-000에서 이 계약이 반복 실패했다. 변경 문자 자체는 과거 기록만으로 복원할 수 없지만 모델의 원문 재출력에 의존하는 연결 방식이 실패 지점이라는 것은 확인했다.

v13은 모델에게 **평가한 문서 ID**만 선택하게 하고 서버가 해당 문서의 실제 원문을 내부 Assessment로 연결한다. 모델이 다시 쓴 문장을 인용으로 수용하지 않는다. 정수 ID 범위·중복·실제 평가한 문서 목록을 검증하며, 8문서/6000자 문맥·최대 4개 선택·2회 루프·기존 비용 한도는 유지한다. 점수 미달 문서를 승격하지 않는다. 정의 충분성·부분 답변·적용 범위 판단은 기존 평가를 유지한다. 내부 발췌 원문 검증도 그대로 통과해야 한다.

인용 단위는 짧은 문장에서 선택된 문서 청크로 넓어진다. 이는 원문 연결을 확실하게 하는 변경이지, 선택된 청크가 모든 생성 주장을 보장한다는 뜻은 아니다. 모델의 잘못된 문서 선택이나 의미 판단은 여전히 가능하고, 해당 부분은 전체 품질 평가가 필요하다.

## 실제 최소 확인

이전 실패 코호트는 보존하고 새 디렉터리에서 ag-000 한 건만 호출했다. 임베딩 1회·Lite controller 1회·Flash 답변 1회. Pro 채점은 하지 않았다. 새 출력 구조가 짧아 controller 출력은 45토큰이었다. 속도/비용 개선율은 단일 사례로 주장하지 않는다.

- 상태 completed, STOP, 비용 메타데이터 완전.
- 원문 검증 거부 0개, exact 연결 2개, complete coverage.
- WHO 문서 페이지 24와 12의 원문 청크가 연결되었다. 원본 페이지 메타데이터 표기를 유지한다.
- 답변은 성인·아동, 총 에너지 10% 미만, 강한 권고를 포함해 저장된 gold 핵심 조건과 수동 대조했다. 추가 5% 권고는 조건부로 구분했다.
- 행의 `correct:false`는 `--defer-judge` 실행기의 미채점 기본값이다. 새 Pro 품질 판정이 아니며 자동 정답률로 해석하지 않는다.

이번 사용·예약 증가 $0.006031. 누적 $2.084143/$5: 비교 $1.348704/$1.70, judge $0.709132/$3.10, 개발 $0.025021/$0.05, probe $0.001286/$0.05, browser $0/$0.10. 미정산 예약 $0.019100 유지. 유료 재시도 없이 1건에서 기능 성공을 확인했다. 실제 사용자 기록·운영 DB는 변경하지 않았다.

이번 결과는 **원문 연결 실패의 기능 수정 확인**이다. 조건별 100건 비교·독립 품질 채점·배포·브라우저 검증·GitHub push 완료를 의미하지 않는다. 기존 실패 사례는 분모에서 지우지 않는다.
