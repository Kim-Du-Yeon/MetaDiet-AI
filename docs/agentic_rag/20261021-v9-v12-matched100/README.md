# v9 → v12 동일 100사례 비교: 첫 실패로 중단

2026-10-21. 기존 사용액과 전체 $5·단계별 예산을 유지했다. 기존 v9 답변 100개와 역사적 채점 100개를 재사용하고, 새 v12는 첫 사례부터 순차 실행했다. 첫 실패 이후 추가 유료 호출을 하지 않았다.

| 항목 | 결과 |
|---|---|
| 동결 사례 | 동일 100시도, 고유 질문 40개 반복; 실제 사용자 성과 아님 |
| 기존 v9 | 저장 답변·채점 100개 재사용; 역사적 정답률 83/100 |
| 새 v12 | ag-000 1건 실행·실패, 99건 미실행 |
| 새 답변 생성·Pro 채점 | 0건 |
| 실행 결과 | 첫 controller의 발췌 3개 모두 원문 검증 실패 (`excerpt_mismatch`) |
| 판단 | 전체 품질·근거 적중률·속도·비용 비교 미완료, 배포 기준 미통과 |

첫 질문은 WHO의 성인·아동 유리당 제한과 권고 강도를 묻는 사례다. 검색·controller 단계에서 실패했고 답변 생성 전에 중단했다. 실패 행의 약 6.888초는 성공 응답 지연이나 성능 개선 근거가 아니다. 기존 실행은 worker 3, 이번 실행은 즉시 중단을 위한 worker 1이므로 통제된 속도 비교도 주장하지 않는다. 미실행 99건을 성공/실패 채점에 섞지 않는다.

확인된 원인은 controller가 반환한 발췌를 원문과 연결하지 못했다는 것이다. 실패 행에는 원문·발췌 쌍이 보존되지 않아 문장 재작성·수치·문장부호·문맥 구성 중 무엇이 원인인지는 확정할 수 없다. 원문 검증을 느슨하게 하거나 재호출하지 않았다. 다음 작업은 유료 재실행 전에 검증 실패 위치를 안전하게 남기는 오프라인 진단과 저장 가능한 개발 fixture 보강이다.

`run-status.json`의 `provider_blocked`는 기존 실행기의 중단 플래그 이름이다. 이번 중단은 provider 장애나 크레딧 소진, 예산 초과가 아니라 원문 검증 실패다.
