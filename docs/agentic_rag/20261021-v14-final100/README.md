# v14 동일100사례 비교

v14의 온전한 인접 청크 회수·문맥 우선 배치·중복 질의 대체 경로를 동결했다. 기존 v9 답변100개와 역사적 채점100개를 재사용 자료로 보존한다. v13 결과는 코드가 다르므로 v14 결과로 재사용하지 않고, 저장 문맥을 쓴 v14 ag-013 단일 smoke도 별도로 유지한다. 새 후보는 동일100시도(고유 질문40개 반복)로 평가하며 독립 사용자100명의 결과가 아니다.

사용자 승인 예산 재배분: 전체$5, comparison $2.60, judge $2.20, probe $0.05, development $0.05, browser $0.10. 시작 누적 사용·예약 $2.270037을 보존한다. 기존 미정산 예약도 유지한다. 한 분할씩 실제 사용량 정산하며 어느 한도에 걸려도 새 호출을 중단한다. 출력 상한만으로 실제 전체 청구액을 확정하지 않는다.

5건 순차 생성→저장된5쌍 native Pro Batch 채점→후보 정답/충실성 판정 통과 후 다음 분할 순서다. 실행/비용/계약 실패 또는 후보 오답/비충실 판정이면 추가 유료 실행 없이 종료한다. coordinator는 실패한 하위 실행을 자동 재시도하지 않는다. 과거 실패 결과는 삭제하지 않는다. 제안되는 full gate는 이전 동결 기준을 유지하며, 단일 중간 분할 성공을 최종 성능으로 주장하지 않는다.

이전 v9 지연은 worker3, 새 후보는 worker1이므로 역사적 지연과의 인과적 속도 개선을 주장하지 않는다. 실패·타임아웃을 분모에 남기고 미실행 시도 수는 별도로 집계한다. 전체 기준 통과 전 배포/운영 브라우저 검증/GitHub push를 하지 않는다. 원시 자료는 `protocol.json`, `identity.json`, `attempts.jsonl`, `packet-*.grades.jsonl`과 각 Batch 정산 기록이다.

## 최종 결과: ag-022 보류로 즉시 종료

v14 23건을 시작해22건 일반 답변·1건 보류가 발생했고77건은 실행하지 않았다. 앞선20쌍의 paired Pro 채점은 후보20건 모두 correct/faithful, 기존19건 correct였다. 이는 조기 중단된 개발 평가의 중간 결과이며 최종100건 정확도나 성능 개선을 입증하지 않는다. ag-020/021/022는 실패 후 추가 호출 금지에 따라 채점하지 않았다. 기존 v9 답변·역사적 채점100개는 재사용했으며 후보 답변은 코드가 달라 새로 생성했다.

ag-013은 이번 실제 검색 경로에서도 후보 correct=true/faithful=true로 통과했다. 원문 발췌 불일치는 재발하지 않았다.

ag-022는 controller가 첫 라운드에 `definition_support=direct`, `stop_reason=sufficient`, `answer_coverage=complete`로 판단하고 KDRI 2025 문서 페이지79의2개 원문을 연결했지만, 최종 QA가 `제공된 자료에서 근거를 찾지 못했습니다.`로 끝났다. 원문 검증 거부0, 비용 메타데이터 완전, provider 오류 없음으로 예산/인증/원문 연결 실패가 아니다. **근거 충분성 평가와 최종 QA 보류가 불일치하는 실행 실패**다. 해당 문맥이 실제 요청 개념의 직접 정의를 충분히 담았는지는 이번 중단 뒤 추가 호출로 판정하지 않았다. `ag022-review.json`에 질문·원시 문맥·답변·텔레메트리를 보존했다.

실행기의 `status=completed`는 HTTP/생성 완료 상태다. `verification_failure`가 표시된 보류1건은 성공으로 세지 않는다. `provider_blocked`는 기존 일반 중단 플래그이며 실제 provider 장애를 뜻하지 않는다. coordinator는 exit2 후 추가 생성·채점·수정·재시도를 실행하지 않았다.
