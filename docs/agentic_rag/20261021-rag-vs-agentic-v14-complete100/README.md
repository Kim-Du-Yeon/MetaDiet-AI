# 일반 RAG 대 Agentic RAG v14 — 조건별100시도 완료

**결론: Agentic RAG를 추가 후보로 구현·실험했으며, 현재는 기존 선택 조합을 유지한다.**
내용 정답률은85%→88%였지만, 근거 충실성·한국어 정답률·근거 페이지 적중·출력 완결성에서 일관된 개선이 없었다. 추가 지연·호출 비용과 평가 조건 차이도 고려했다. 현재 운영 조합은 PyPDF/recursive +3072차원 Gemini embedding + Hybrid/no-reranker이며, 저메모리 원격 환경에서는 dense fallback을 사용한다. Agentic 기본OFF를 바꾸지 않았고 공개 배포를 실행하지 않았다.

## 실험과 재사용

- 고유40질문/20사실그룹을 반복한 조건별100시도. 독립 질문100개나 실제 사용자100명 성과가 아니다.
- 일반 RAG는 저장된20261020 baseline100답변을 재사용했다. 평가 당시 source는 단일 retrieve→QA였으며 Agentic 루프가 없는 기준선이다.
- v14 Agentic은 이미 실행한23시도(ag-022 보류 포함)를 재사용하고 나머지77시도를 추가했다. 실패한 사례를 성공 사례로 바꾸지 않았다.
- 비교군이 바뀌므로 기존 v9-v14의20쌍 판정을 새 비교 판정으로 재사용하지 않았다. 새로운 일반 RAG/v14 payload100쌍을 동일 Pro paired rubric으로 채점했다. A/B 배치는 시도 번호에 따라 교대했다.
- 모델·질문·코퍼스·namespace·dense k4/no-reranker는 같지만 **과거 기준선과 QA 프롬프트/worker수가 다르다**. 따라서 이 비교는 역사적 기준선 대 현재 개선 묶음의 관측이며 순수한 Agentic 루프만의 인과적 ablation이 아니다. Hybrid+Agentic를 직접 검증한 결과도 아니다.
- 사람이23시도 결과를 본 뒤 중단 정책을 바꿨다. 개별 오답·보류·요청 실패는 분모100에 유지하고 계속 측정했다. 사전등록 독립 평가로 표현하지 않는다.

## 전체 결과

| 지표 | 일반 RAG | Agentic v14 |
|---|---:|---:|
| 시도/채점 분모 |100|100|
| Pro 내용 정답 |85/100|88/100|
| Pro 이진 근거 충실성 |99/100|97/100|
| 영어 내용 정답 |40/50|45/50|
| 한국어 내용 정답 |45/50|43/50|
| 정확한 무근거 보류 문구 |8/100|4/100|
| 근거 페이지 적중 |79/100|78/100|
| 외부 호출/요청 실패 |1/100|2/100|
| 생성 종료 MAX_TOKENS |미수집|5/100|
| 정답이며 STOP 정상 종료 확인 |과거 메타데이터 없음|84/100|
| 두 번째 검색 수행 |0/100|8/100|
| 요청 p50 |11.507초|15.469초|
| 요청 p95, nearest-rank |18.987초|25.737초|
| 알려진 생성 모델 토큰 비용/100시도 |$0.530120|$0.756793|

**정답률88%는 내용 판정이다.** 출력 한도5건 중4건이 핵심 사실을 답해 Pro의 correct=true를 받았다. 이4건까지 정상 완료 요구를 적용하면84/100이다. 정답률을 유리하게 보이도록 종료 오류를 숨기지 않는다. 과거 일반 RAG에 같은 finish 메타데이터가 없어 정상 종료 포함 정답률을0%로 취급하거나 새84%와 직접 비교하지 않는다. Agentic의 finish 기록은96건이며,2건 요청 실패와2건 모델 생성 없이 보류된 사례에는 finish가 없다.

이진 충실성은 이번 Pro rubric의 boolean 판정이며 **Ragas faithfulness가 아니다**. Agentic의 Ragas context recall/faithfulness를 이번에 새로 계산했다고 표기하지 않는다. [기존 검색 조합·Ragas 실험과 선택 근거](../../rag_experiments/RAG_RECIPE_DECISIONS.md)를 별도 표로 연결했다.

## 남은 오류와 해석

- ag-022/062: 충분성 평가와 최종 QA 보류가 일치하지 않거나 요청 개념의 직접 근거가 부족했다.
- ag-026/027/053/066/067/073 등: 필요한 지표·수치·적용 범위가 검색 문맥에 충분히 담기지 않아 전체 또는 일부를 답하지 못했다. ag-013은 첫 반복에서 통과했지만 같은 사실의 후속 ag-053에서 다시 누락이 나타나 단일 smoke 성공을 일반화할 수 없었다.
- ag-036/038/068/078/094: MAX_TOKENS. 일부 핵심 사실이 맞아도 완결된 사용자 응답으로 보장하지 않는다.
- ag-049: TimeoutError, ag-087: GoogleAPIError. 실패도 분모에 남겼다. ag-049의 관측 지연은391.463초였고 제외하지 않았다. 로컬 테스트/대기에도 큰 지연이 관측돼 원인을 provider에만 귀속하지 않으며 운영 SLA로 일반화하지 않는다.

영어 정답은 늘었지만 한국어 정답은 감소했다. 재검색은8시도만 수행되어 첫 평가의 충분성 오판을 항상 보완하지 못했다. 원문을 재출력시키던 발췌 불일치는 문서ID→실제 원문 연결로 보완했으나, 원문 일치가 의미적 충분성이나 답변 완결성을 보장하지는 않았다. 상세 문맥·판정은 `error-cases.json`에 보존했다.

## 채택 판단

일반 dense 기준선 대비 내용 정답+3%p만으로 운영 Hybrid를 Agentic으로 교체하지 않는다. 정답률95% 기준을 충족하지 못했고, 충실성·한국어 정답·근거 페이지 적중·응답 완결성은 개선되지 않았다. 과거 지연과 새 지연의 worker/시점이 달라 속도 증감은 인과적으로 해석하지 않지만, 관측된 지연과 호출 부담도 추가 도입을 정당화할 만큼의 우위를 보이지 않았다.

따라서 **기존 선택 조합 유지 / Agentic은 구현·실험 완료 후보 / 운영 미채택**으로 기록한다. 기존 Hybrid의 독립20문항 Ragas 결과와 이번 반복 개발100시도를 하나의 순위표로 합산하지 않는다. 같은 현재 QA 프롬프트·실행 조건의 Hybrid 대 Hybrid+Agentic 및 독립 질문 검증 없이 운영 우월성을 주장하지 않는다. 이들은 이번 완료를 위한 추가 작업이 아니라 결론의 적용 한계다.

## 비용·재현 자료

이번 단계 새 사용·예약 증가 **$1.251818**, 누적 **$3.781200**. 기존 예약과 사용액을 보존했다. 새 Batch는41/34/25쌍으로3개 모두 완료·정산했다. 미완료 새 Batch0개. 이전 불명 예약$0.019100은 임의 환급하지 않았다. 이번 새 생성77건·새 Pro100쌍 외 추가 재생성/재채점은 하지 않았다.

비교표 비용은100시도에서 확인된 생성 모델 토큰 추정이며 judge비용은 별도다. 일반 RAG의 실제 임베딩 usage는 미수집이어서0원으로 단정하지 않는다. Agentic은 임베딩 토큰 사용량100건을 기록했으나 실패 모델2건의 일부 사용량은 미확정이다. 전체 비용 완전성을 과장하지 않는다. 임베딩 바이트 대용치와 실제 토큰 비용은 `final-summary.json`에 분리했다.

`cases.json`, `attempts.jsonl`, `grading.grades.jsonl`, `final-summary.json`, `error-cases.json`, `data-integrity-audit.json`이 원시 근거다.200개 판정의 payload/rubric/model/A-B mapping을 다시 검증했다. `historical-normal-source.py.txt`와 두 identity로 기준선이 일반 RAG임을 추적한다. 기존 v9-v14 판정은 ancillary 자료로만 보존했다. 실행 source 사본과 artifact 해시는 함께 저장한다.

실행 방법은 동결 driver 사본을 repo의 tmp에 복사해 원래 ROOT 위치를 유지하고 `--allow-paid`를 명시하는 방식이다. 저장 결과 요약·검사는 provider 호출 없이 실행할 수 있다. 실제 API 재실행은 새 디렉터리·코드/사례 동결이 필요하며 이100건의 실패를 덮어쓰지 않는다.
