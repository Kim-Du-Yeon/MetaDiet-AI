# 표 해석·부분 답변·필수 조건 보존 — 100쌍 재검증 완료, 미채택

크레딧 반영 후 임베딩·Flash-Lite·Flash 최소 호출 성공. 임베딩 원본 응답에서 입력10토큰을 확인했다. Pro 온라인 호출은429였으나 별도 Batch 할당량의 개발24답변 평가는 성공했다. 이전402 기록은 삭제하지 않고 preflight-blocked.json에 보존한다.

## 개발·고정 과정

이전 근거 보존 v2의 코드와 v1 assessor를 baseline으로 고정했다. 최초 후보(controller v2/recipe v3)는 합성 개발12개 중10개에서 의도한 충분성 판단과 일치했다. 범위 제한을 답할 수 있는 사례와 정의+미확인 추가요구 사례를 불필요하게 보류했다.

문항별 골드나 숫자를 넣지 않고, sufficient의 의미를 ‘요구한 모든 내용을 제공할 수 있음’에서 ‘범위를 지킨 근거 기반 답변이 가능함’으로 명확히 했다. controller v3/recipe v4로 버전을 올리고 같은 별도 개발12개 전체를 재검증했다. 긍정8개와 근거 부족4개에서 모두 의도한 판단을 확인했다. Pro Batch는 baseline 정답8/12·충실12/12, 후보 정답12/12·충실12/12로 판정했다. 소규모 합성 기능 확인이며 성능 일반화의 근거가 아니다.

후보는 확인된 핵심은 답하고 확인되지 않은 추가 요구만 보류한다. 표의 행·열·단위·범례·각주, 대상·적응증·예외·권고 강도·날짜/버전·계산식 출처와 비교 조건을 보존하도록 안내한다. 빈칸/절단만으로 없다고 단정하거나 다른 집단 값을 적용하지 않는다. QA 및 실제 DietTeam 도구 결과에 충분한 근거가 있을 때만 추가 답변 지침을 전달한다.

점수 게이트·최초 근거 보존·8문서/6000자·검색2회·평가2회·기본35초·공유 호출 예산 및 오류 시 보류는 유지한다. 실제 운영 지침이 아닌 가상 표와 개정 메모를 사용한 별도 개발셋이며 기존40문항의 질문 문구와 겹치지 않는다.

## 본 비교

동결40문항을 반복한 조건별100시도(총200) 생성과 Pro 최종 채점 완료. 독립100질문 또는100명의 사용자 결과가 아니다. baseline과 candidate 모두 새로 생성하며 A/B Pro Batch로 독립 채점한다. 코드·질문·골드·판정 기준은 본 비교 중 변경하지 않는다. 기준 미달로 운영 개선을 주장하거나 배포하지 않는다.

실험 전용 계측에서 SDK가 버리는 usageMetadata.promptTokenCount를 변환 전 원본 응답에서 읽는다. 실제 토큰이 없으면 비용 미완료로 남긴다. 바이트 프록시는 청구 토큰으로 쓰지 않는다. 가격표2026-10-21 재확인, 서비스 비용과 Batch 평가 비용은 분리한다. 실제 청구서·세금은 별도다.

사전 배포 기준: 정답률95%·최소2%p개선, 충실도·근거 페이지·실패 비열등, 중앙값/p95각1.5배이내, 비용완료·2배이내를 모두 만족해야 한다. 운영 기본OFF. 통과 시에만 배포와 실제 브라우저 검증을 진행한다.

관측 p95는 약4.3% 감소했지만 API 소계 비용은 약6.8% 증가했다. 작은 반복 개발셋에서의 관측값이며 통계적 우월성이나 공개 서비스 전체 성능을 입증한 것은 아니다. 비용은 제공자 사용 토큰과 고정 단가의 추정치로, Pinecone/호스팅·세금·청구서 및 개발·최소 호출 비용을 포함한 총비용이 아니다. 두 답변을 함께 채점한 Pro 호출 비용은 양쪽에 절반씩 배분했다. 별도 개발24답변 Pro 비용은 총$0.033732로 최종 평가와 구분한다.

사전 게이트의 정답률95%·최소2%p개선 두 항목이 실패했다. 나머지 충실도·근거·실패·지연·비용 조건은 통과했으나 **전체 rollout_gate=false**다. 코드와 문서는 [skip render]로 공개하고 운영 AGENTIC_RAG_ENABLED=false를 유지한다. 후보 배포·실제 브라우저 기능 검증은 수행하지 않았다. 브라우저 제어 준비의 초기화 오류도 별도로 기록했지만, 이번 미배포 결정의 이유는 품질 게이트 미달이다.

## 오답·회귀 원인과 다음 개발 범위

[쌍별 변화](paired-quality-changes.json): 보류했던 음의 에너지 균형4시도는 정답으로 회복됐지만, 류신 수치3시도와 활동 수준1시도가 오답으로 바뀌어 상쇄됐다. 이를 전체 정답률 개선이라고 포장하지 않는다. 생성·검색의 확률적 변동도 있어 각 변화의 인과 효과를 단정하지 않는다.

후보 오답11시도는4개 유형(반복을 제외하면6개 질문)에 해당한다.

- 에너지 상한 기준4시도: 표에 EER만 보이는 상황에서 답변 모델이 기준 부재를 확정하지 못해 보류했다. 빈칸만으로 임의 결론을 내리도록 완화하지 않았다.
- 핵심 수치 문맥 미포함3시도: 해당 PDF 페이지는 적중했으나 전달된 청크에700–3000 mg이 없었다. controller는 일반적인 관련 설명만으로 충분하다고 판정해1회 검색에서 끝났다. 페이지 적중과 질문의 핵심 수치 근거 확보는 다른 지표다. 청크가 검색되지 않았는지 또는 전달 단계에서 누락됐는지는 이 실행의 최종 문맥만으로 모두 확정할 수 없다.
- 적용 범위 누락3시도: 비만 진료지침이라는 문서명과 치료 맥락은 답했으나 모든 건강한 성인에게 일반화할 수 없다는 조건은 빠졌다. 문서 메타데이터에는 임상 적용 범위가 있으나 QA의 문맥 헤더에는 표시되지 않았다. 실제 DietTeam 도구 결과는 population을 별도 필드로 전달하므로 이 QA 경계 비교를 운영 대화 전체 결과와 동일시하지 않는다.
- 필수 항목 불명확1시도: 활동적·매우 활동적을 분류 목록으로 언급했지만 별도 에너지 추정치를 제시한 수준으로 명확히 답하지 못했다고 Pro가 판정했다.

[원본 오답](candidate-error-review.json), [문맥 계약 확인](context-contract-review.json)을 함께 공개한다. Pro 자동 판정은 임상 전문가 또는 독립 인간 검수와 다르며, 판정에 맞춰 골드나 루브릭을 바꾸지 않았다.

다음 개발은1) 임의 추가 요구와 질문의 필수 수치 요구를 구분한 coverage 검사,2) 적중 페이지의 실제 근거 구간 확보,3) 적용 대상 메타데이터를 평가/생성 문맥에 일관되게 전달,4) 표의 범례와 정의 문장 확인이다. 별도 개발셋으로 보완하고 새로운 동결 비교를 설계해야 하며, 이번 점수를 올리려고 동일 답변을 재생성하거나 평가자를 바꿔 채점하지 않았다.
