# Hybrid vs Hybrid+Agentic RAG: 동일 조건100시도씩 완료

**판단: 기존 Hybrid/no-reranker 유지, Agentic 운영 미채택.** 동일한 최종 답변 프롬프트·모델·검색 설정·실행 환경에서 새로 생성한100쌍을 끝까지 평가했다. Agentic 정답률이89%에서80%로 낮아졌고 지연·비용은 증가했다. 구현·비교 실험 완료와 운영 적용을 구분한다. 운영 설정은 변경하지 않았다.

## 짝별 변화와 채택 이유

100쌍 중 양쪽 정답79건,양쪽 오답10건,Hybrid 오답→Agentic 정답1건,Hybrid 정답→Agentic 오답10건이었다. 정답률 차이는 **-9%p**,중앙값 지연 **+50.9%**,p95 **+45.2%**,생성 토큰 비용 추정 **+36.4%**다. 이 조합에서 추가 루프를 서비스 기본값으로 켤 실익을 확인하지 못했다.

- `ag-014/054/094`: baseline 문맥의700mg 관련 범위가 Agentic 최종 문맥에서 빠지고 유사한1–3g 문구로 답했다. `ag-014`는 문맥4998→6000자,초기 문서 보존2개,충분 판정 후1회 검색으로 종료됐다.
- `ag-018/058/098`: baseline의 `at least 24` 핵심 조건을 잃고 다른 문맥의 `up to 24`로 답했다. 관련 주제만 검색했다고 질문의 정확한 조건을 충족하지는 못했다.
- `ag-024/064`: 직접 정의를 찾는 동안2회 한도에 도달해 최종 문맥을 비우고 답변을 보류했다. baseline은 정답이었다.
- `ag-038/078`: 동반 질환 목록의 필수 조건이 최종 문맥에서 충분히 유지되지 않아 답변을 보류했다. 모델 출력 잘림은 아니었다.
- `ag-032`: Agentic이 기본 활동 수준 근거를 보완해 baseline 오답을 회복한 사례다. 장점도 보존한다.

이 관찰은 인접 청크 확장·근거 선택·6000자 문맥 조립이 좋은 기존 근거를 밀어낼 수 있음을 보여준다. 각 구성요소의 기여를 따로 분리한 실험은 아니므로 한 원인에 모든 오답을 귀속하지 않는다. [문맥의 핵심 표현 유무·길이·실제 종료 이유](mechanism-examples.json),[모든 오류와 judge 사유](error-cases.json)를 공개했다. 이번 비교 중 후보를 수정하거나 실패 사례를 재생성하지 않았다.

## 통제 조건과 한계

[동결 프로토콜](protocol.json),[방법·재현 명령](METHOD.md),[실행 identity](identity.json).

양쪽 모두 strict Hybrid(Dense+Kiwi BM25+RRF),k4/candidate20,no-reranker,같은4139청크/3072차원 namespace를 사용했다. 동일 QA_PROMPT·정적 ANSWER_GUIDANCE·문맥 포맷,Flash/temperature0/LOW/4096토큰,3개 pair worker와AB/BA 균형 순서를 고정했다. Agentic의 동적 답변 지침은 제거하고 검색 제어 패키지의 영향을 비교했다. 추가 Lite 평가·재작성·인접 청크는 Agentic 조건의 처리 비용에 포함했다. 기존 과거 답변과 채점은 섞지 않았다.

**40개 질문·20개 사실그룹을 반복한 개발100시도씩**이다. 후보 개발에 쓰인 질문이며 독립100문항·실제 사용자 성공률·임상 성능으로 일반화할 수 없다. 사실그룹 cluster bootstrap의 탐색적 정답 차이95% 구간은 -19~0%p로,새로운 질문 전체에 대한 통계적 열등성을 확정하는 검정도 아니다. 같은 Windows 프로세스에서 두 조건을 균형화했으나 전용 무부하 장비나 공개 Render의512MiB/cold start 환경은 아니다. 강제 Hybrid 비교와 운영 저메모리 dense fallback을 구분한다.

Pro 자동 판정에도 한계가 있다. 예를 들어 비어 있는 문맥에 대한 보류를 충실하다고 본 사례들과 다르게 `ag-024`의 보류는 충실하지 않다고 판정됐다. 원본 판정을 임의 수정하지 않았고,정답률과 원시 사유를 함께 제시한다. 문서 내부의 유사하지만 다른 수치와 GOLD의 엄격한 요구 범위도 오류 해석에 포함해야 한다.

## 비용·검증·보존

신규 생성 모델+임베딩 추정 $0.692813,Pro paired Native Batch100요청/200판정 추정 $0.650066,**이번 토큰 비용 추정 합계 $1.342879**다. provider 사용량과 동결 요율에 기반한 추정이며 실결제 청구액은 아니다. 모든 새 사용량을 정산했으며 과거 미확인 예약$0.0191은 유지했다.

기존 장부 $3.781200→$5.139139(증가 $1.357939). 장부는 캐시 입력을 정상 입력 요율로 보수적으로 계산하고 호출별 micro-dollar 올림을 적용하므로 캐시 할인 적용 토큰 추정 합계와 다르다. 과거 $5 중단 조건 철회 후 이번 평가 프로세스에만 $15 안전 한도를 적용했고,운영 및 기존 기본 $5 설정은 유지했다. 예산을0으로 초기화하지 않았다.

전체 백엔드 **1654 passed / 기존1 skipped**,새 통제 조건·비용 관련 후속 검사 **25 passed**. 임시 경로 권한 오류는 [pytest 공식 임시 경로 안내](https://docs.pytest.org/en/stable/how-to/tmp_path.html#temporary-directory-location-and-retention)에 따라 workspace 내 전용 `--basetemp`를 사용해 해결했다. 테스트를 제거하거나 새로 skip하지 않았다. 프론트엔드·운영 코드 변경 및 공개 배포는 이번 범위에 없다.

## 포트폴리오 표현

“Hybrid RAG에 제한된 평가·재작성·재검색 Agentic 루프를 구현하고,동일 프롬프트·모델·환경에서 조건별100시도를 실패 포함 비교했다. Pro 정답89→80%,중앙값6.44→9.71초,생성 비용약36% 증가를 확인했다. 일부 근거 회복보다 핵심 수치 누락·불필요한 보류의 손실이 커 기존 Hybrid/no-reranker를 유지하고 Agentic은 실험 기능으로 남겼다.”

[기존 Parser·Chunking·Embedding·검색·Jev와의 비교 인덱스](../../rag_experiments/RAG_RECIPE_DECISIONS.md). 과거 dense85/88% 비교는 프롬프트·worker 차이가 있는 역사적 결과로 유지하며 이 통제 비교와 합산하지 않는다.
