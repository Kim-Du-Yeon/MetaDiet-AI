## 문제와 구현

ag-022 저장 기록에서는 관련 개념의 정의를 찾았지만 질문 대상 자체를 정의하지 못한 문맥을 충분하다고 판정했다. 단순히 질문 단어가 등장하거나, 원문 발췌가 정확히 일치한다고 해서 질문에 답할 수 있는 것은 아니다.

controller-v12는 `definition_support`를 구분한다.

| 값 | 의미 |
|---|---|
| direct | 원래 질문의 개념 자체에 대한 의미·정의 관계·판별 기준을 직접 설명함 |
| related_only | 다른 개념이 질문 대상을 유지·예측·사용한다고 설명할 뿐임 |
| missing | 질문 대상의 직접 정의가 없음 |
| not_requested | 정의를 묻는 질문이 아님 |
| not_assessed | 예전 저장 판정의 호환 기본값. 정의 근거가 검증됐다는 뜻이 아님 |

프롬프트는 관련 개념의 언급을 직접 정의로 간주하지 않도록 별도 가상 예시를 제공한다. 실제 영양 정답·ag-022 페이지·정의는 운영 규칙에 넣지 않았다.

`definition_evidence.apply_definition_gate`는 명시적 정의 요청 또는 모델이 분류한 정의 요청에서 direct + 비어 있지 않은 발췌가 아니면 충분성 true를 취소한다. 누락 정의를 `missing_core`에 추가하고 원래 질문의 개념을 유지한 재검색 질의를 만든다. 이때 관련 설명을 부분 답변 근거로 승격하지 않는다. 최대 두 번째 검색 이후에도 직접 정의가 없으면 계속 보류한다.

직접 정의가 있고 다른 수치만 빠진 경우에는 기존 부분 답변 흐름을 유지한다. 직접적인 범위 제한·부정형 정의도 보편 집단으로 확장하지 않고 답할 수 있다. 원문 공백·수치 검증은 그대로 수행하며, direct라는 모델 분류만으로 조작된 발췌가 통과하지 않는다. 원래 질문은 모든 재평가에서 동일하게 유지한다.

정의/뜻/의미 요청의 명시 패턴은 보수적으로 인식한다. '정의 말고 분량만' 같은 단순 분량 요청은 그 단어만으로 강제 재검색하지 않는다. 간접 구어체의 질문 의도와 의미적 지원 분류는 모델의 새 필드에 의존한다.

## 별도 개발셋·저장 기록 검증

`test_definition_evidence.py`의 가상 Nivo·Vela·솔·고리 사례는 기존 100문항·독립 최종20과 분리했다. 예를 들어 'Quota가 reserve balance를 유지한다'는 관련 설명이고, 'reserve balance가 두 값이 같은 상태를 뜻한다'는 직접 정의로 분류한 fixture를 사용한다.

**모델 응답 분류는 mock으로 제공했다.** 이 테스트는 관련 분류 시 재검색하도록 강제하는 코드와 직접 정의의 종료 경로를 검증하며, 실제 Lite가 해당 범주를 정확히 판단한다는 성능 증거가 아니다. 15개 새 테스트에 한국어·영어, 반복 제한, 직접 정의 없음, 오래된 판정, 범위 제한, 빈 발췌, 단순 분량 요청, 공유 예산에 의한 추가 검색 차단을 포함했다.

저장된 ag-022의 예전 판정은 새 정의 분류가 없다. 이제 원문 공백 검증에 통과해도 그 저장 판정만으로 직접 정의가 검증됐다고 인정하지 않고 mock 검색·평가 2회 후 보류한다. 이전 공백 검증 테스트는 이 의도된 동작에 맞춰 갱신했고 독립적인 공백 원문 일치 테스트는 그대로 유지했다. 테스트 삭제·skip 추가 없음. 실제 과거 기록은 수정하지 않았다.
