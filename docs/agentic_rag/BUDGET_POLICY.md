# 평가 비용 제한 — 2026-10-21

이번 변경은 오프라인에서만 검증했다. 새 생성·채점·임베딩·Batch 제출은 실행하지 않았다.

## 예산

| 단계 | USD 상한 |
|---|---:|
| probe: 최소 연결 확인 | 0.10 |
| development: 실패 사례 확인 | 0.25 |
| comparison: 최종 전후 비교 | 3.00 |
| judge: 저장 답변 평가 | 1.00 |
| browser: 공개 확인용 예약 | 0.15 |
| 전체 캠페인 | 5.00 |

단계별 상한의 합은 $4.50이다. 남은 $0.50은 자동으로 어느 단계에도 배정하지 않는다.
이전에 발생한 비용과 계정 전체 청구액은 이 **새 캠페인** 예산에 합산하지 않는다.

## 자동 차단

`backend/scripts/eval/eval_budget.py`의 SQLite 장부가 호출 전 예약과 사용량 정산을 담당한다.
기본 장부는 저장소의 `tmp/eval-budget.sqlite`이며 Git에서 제외된다. 같은 캠페인의 모든
프로세스와 재실행은 **같은 장부**를 사용해야 한다. 새 경로를 지정하거나 장부를 지우면
별도 예산이 되므로, 재시도 목적으로 이를 변경하지 않는다.

- SQLite 쓰기 트랜잭션으로 동시 프로세스의 비용 예약을 직렬화한다.
- 이미 사용한 비용과 진행 중 예약액을 합쳐 단계/전체 상한을 검사한다.
- 예약 불가 시 실제 전송 전에 캠페인을 중단한다. 중단 상태도 저장하여 재시작 후 유지한다.
- 원시 사용량이 검증되면 예약액을 실제 추정 비용으로 정산한다. 사용량 누락·오류·취소·
  프로세스 종료·미완료 Batch 제출은 예약액을 유지한다. 실패 비용을 0으로 간주하지 않는다.
- 공급자 사용량이 예약을 초과하면 해당 비용을 그대로 기록하고 캠페인을 중단한다.
- SDK 내부 재시도는 1회 시도로 제한한다. 외부 재시도도 매번 다시 예약해야 한다.
- 알 수 없는 모델/요금, 무제한 출력, 스트리밍, 미디어, 외부 도구 및 파일 기반 Batch는 차단한다.
- SDK 전송 앞에서 차단하므로 검색 컨트롤러가 오류를 안전한 답변 보류로 바꿔도 유료 호출이
  계속되지 않는다. 예산 중단은 일반 `Exception` 처리에 흡수되지 않는다.

예약은 직렬화한 텍스트의 UTF-8 바이트 수에 프로토콜 여유 2,048을 더한 입력량과
명시적 최대 출력량/추론 예산으로 보수적으로 계산한다. 실제 토큰 카운트 API는 호출하지 않는다.
평가 생성은 두 조건 모두 최대 출력 2,048, 번역은 256으로 고정한다. 이 설정 변경은
새 비교의 실행 조건에 기록해야 하며 과거 실행의 속도·품질과 그대로 혼합하지 않는다.
요금은 현재 실험에 동결된 Gemini 모델 단가를 사용한다. 할인 캐시는 예약 계산에 반영하지 않는다.

## 적용 범위와 실행 기본값

아래 다섯 평가 CLI는 `--allow-paid`가 **없으면 API 실행 전에 중단**한다.
이 문서는 유료 실행 허가를 의미하지 않는다.

| 평가 CLI | 고정 예산 단계 |
|---|---|
| benchmark_agentic_rag.py | comparison |
| develop_agentic_policy.py | development |
| batch_agentic_judges.py | judge |
| rejudge_agentic_rag.py | judge |
| judge_agentic_pairs.py | judge |

`--budget-ledger`로 동일 캠페인의 장부 경로를 공유한다. Batch는 기본 최대 10개씩 분할하며,
남은 예산보다 분할 예약액이 크면 제출 항목 수를 줄인다. 한 항목조차 들어가지 않으면
실제 제출 전에 중단한다. 상한이나 출력 제한은 자동으로 변경하지 않는다.
한 번에 미완료 Batch는 하나만 유지한다. 완료 후 응답 키·원시 토큰 사용량·추론 토큰을
검증하고 실제 사용량 기반 비용으로 정산한 뒤, 사용하지 않은 예약액을 해제한다.
이는 공급자 청구서가 아닌 동결 단가에 따른 추정치다. 캐시 입력은 Batch 할인을 이중 적용하지 않는다.

이 가드는 위 평가 CLI의 Gemini SDK 호출을 제한한다. 실제 브라우저가 호출하는 운영 서버,
다른 평가 스크립트, 다른 애플리케이션, Pinecone/Render 요금 또는 Google 계정 전체 지출을
차단하는 클라우드 청구 한도는 아니다. probe/browser 금액은 장부에서 예약할 수 있으나
해당 운영 브라우저 경로에 자동 연결된 것은 아니다. 유료 공개 검증 전에 별도 연동이 필요하다.

## 저장 답변 재활용

기존 답변·검색 문맥·실패 행을 덮어쓰거나 다시 생성하지 않는다. 기존 `--reuse-valid`와
Batch `old`의 유효 평가 제외 경로를 유지한다. 재채점은 저장된 답변만 입력으로 사용하며
생성 비용을 다시 발생시키지 않는다. 이미 유효한 채점 결과의 재사용 비용은 0이다.
이전 200시도와 새 조건의 결과는 합쳐서 새로운 100쌍 성능이라고 보고하지 않는다.

## 오프라인 검증

신규 테스트는 동시 예약, 전체/단계 상한, 재시작 후 중단 유지, 알 수 없는 사용량,
실제 비용 초과, SDK 동기·비동기 전송, Batch 직렬화, 재시도 제한, 기본 실행 차단을 검사한다.
실제 SDK 직렬화 테스트도 전송 계층을 가짜 응답으로 교체하며 API 키는 가짜 문자열만 사용한다.

실제 제한 실행 결과는 [예산 중단 기록](20261021-budgeted-validation/README.md)에 보존했다.
이후 본 비교 실행기는 첫 생성 전에 최종 Pro Batch 채점의 출력량 예약 하한도 검사한다.
구조화 출력을 위한 함수 선언은 입력량에 포함해 허용하지만 외부 요금 도구는 계속 차단한다.

## 분할 제출·정산 (후속 구현, 실제 제출 전)

`batch_agentic_judges.py old`는 저장된 응답에서 유효한 기존 평가를 제외해 분할 캠페인을
만든다. `pairs`는 기존과 동일하게 완전한 100쌍을 요구한다. `--chunk-size` 기본값은 10이며
상한 100이다. 최초 호출은 최대 한 분할만 제출하고 반환한다. 캠페인 파일과 `.parts/`의
개별 작업 기록이 재실행 지점이며, 원본 답변은 수정하지 않는다.

- `collect --job <campaign.json>`: 상태·응답 수집과 정산만 한다. 다음 작업을 제출하지 않는다.
- `advance --job <campaign.json>`: 이전 작업을 수집·정산한 다음 최대 한 분할을 제출한다.
- 두 명령 모두 기존의 `--allow-paid` 명시 없이는 실행되지 않는다. 이번 작업에서는 실행하지 않았다.
- 동일 모델·답변·질문·골드·문맥·루브릭·출력 제한·장부·분할 설정의 해시가 달라지면 재개를 차단한다.
- 작업당 예약 ID를 공급자 job ID와 연결한다. SDK 전송에서 이 예약을 재사용하므로 이중 예약하지 않는다.
- 정산은 SQLite 트랜잭션으로 한 번만 반영한다. 동일 응답 재수집은 비용/환급을 중복 반영하지 않는다.
- 응답 순서는 키로 정렬한다. 키 누락·중복, 토큰 사용량 누락, 불명확한 제출 결과에서는 예약을 유지하고
  다음 분할을 제출하지 않는다. 파싱에 실패한 유료 응답도 사용량이 있으면 비용에 포함한다.
- 종료 상태라도 사용량이 없으면 0원으로 처리하지 않는다. 이후 사용량이 확인되면 다시 수집해 정산할 수 있다.
- 중단 후 재시작 시 기존 작업을 재제출하지 않는다. 제출 결과를 알 수 없는 작업이나 오래된 lock 파일은
  운영자가 확인해야 한다. 자동 재제출·재채점은 하지 않는다.
- 완료하면 캠페인과 같은 이름의 `.grades.jsonl`에 분할 결과를 합치며 실패 행도 유지한다.
- 전체 비용이 예산에 맞는다는 보장은 아니다. 분할 예약을 낮추되 누적 실제 비용은 여전히 $1/$5에 제한한다.

생성 전 채점 가능성 검사는 이제 **첫 분할(기본 최대 10개)**의 출력량 하한을 검사한다.
전체 100쌍의 최대 예약액을 한꺼번에 요구하지 않는다. 실제 제출 시에는 해당 분할의 입력·출력
전체 예약액을 다시 검사한다.

공식 기준: [Batch API](https://ai.google.dev/gemini-api/docs/batch-api),
[모델별 Standard/Batch·캐시 요금](https://ai.google.dev/gemini-api/docs/pricing).
실제 장부의 이전 중단 상태·잔여 예약·사용액은 초기화하지 않았다. 유료 재개는 별도 요청이 필요하다.
