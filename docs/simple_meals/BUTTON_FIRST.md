# 버튼 중심 식사 입력

일반 음식의 g·조리법을 반복 확인하던 흐름을 기본값과 선택 카드로 바꿨다. 미등록 제품을 입력해도 나머지 식사까지 영양표 입력 때문에 막지 않는다.

## 사용자 예시와 동작

`오늘 아침에 밥 한공기랑 삼겹살 200g 그리고 돼지바 아이스크림 1개, 라이스페이퍼 8장`

- 밥 200g, 삼겹살 대표 구이 기준 200g, 라이스페이퍼 장당 10g으로 80g 적용. 조리법·정확한 g 추가 질문 없음.
- 돼지바는 일반 아이스크림 기준 사용 / 기입하기 / 제외하기 버튼. 일반 아이스크림은 앱 분량 70g과 CSV 바닐라 아이스크림 기준이며 돼지바 제품 고유 영양값이 아니다. 사용자가 선택해야 대체된다.
- 기입하기를 눌러야 기준량·섭취량·열량·탄단지 입력 칸이 열린다. 입력 중에도 제외하거나 전체 취소할 수 있다.
- 대표값 없는 음식은 기입 또는 제외. 미확인 음식 모두 스킵과 전체 취소 제공. 모두 제외하면 빈 기록 대신 취소 안내.
- 선택 적용 뒤 전체 식사 확인 카드에서 이대로 기록을 눌러야 실제 저장. 제외된 음식은 합계·기록에서 빠졌다고 표시.
- 브랜드 대체 기준·원래 요청 이름·제외 목록을 기록 metadata에 보존. 사용자 영양표는 해당 기록만 사용하며 공용 DB에 추가하지 않는다.

## 구현과 정확성 경계

LangGraph, 사용자 확인, proposal 버전·중복 확정을 유지한다. `/nutrition/meal-choices`는 JWT 소유자의 대화 checkpoint에 보관된 식사와 선택 ID를 사용한다. 클라이언트가 전체 식사나 영양 DB 수치를 주입하지 않는다. 반복 요청은 같은 request ID와 동일 선택에서만 기존 제안을 반환한다. 미래일·비정상 영양표·중복/누락 선택을 차단한다.

단순 음식 목록에서 미등록 항목을 발견하면 모델 없이 버튼을 준비한다. 수량을 편집하거나 선택 적용할 때도 서버 DB 조회·계산을 사용한다. 대표값이 없는 모든 음식의 영양을 자동 추정하는 기능은 아니다. 복잡한 조언/수정/계획 요청은 기존 Agent 경로를 유지한다.

## 실패 원인과 해결

- 입력 예시가 `한공기랑`, `그리고`, 기본 `삼겹살`에서 단순 파서를 벗어났고, 기존 Agent 지시문이 분량 질문과 전체 보류를 강제했다. 연결 표현·대표 삼겹살을 추가하고 질문 지시문을 기본값/버튼 선택으로 바꿨다.
- [Python 정규식 문서](https://docs.python.org/3/library/re.html)를 참고해 명시 수량과 연결 표현의 경계를 처리했다. 알려진 이름의 접두부만 읽어 다른 제품을 일부 저장하지 않는다.
- [React 조건부 렌더링](https://react.dev/learn/conditional-rendering)을 따라 선택 카드와 직접 입력 폼을 분리했다. 직접 입력을 원하지 않으면 폼 자체가 열리지 않는다.
- 테스트 수집 중 동명 모듈 충돌을 확인했다. [pytest import 문서](https://docs.pytest.org/en/stable/explanation/pythonpath.html)의 고유 파일명 규칙에 따라 통합 테스트 파일명을 구분해 해결했다. 테스트를 삭제하거나 skip하지 않았다.
- 브라우저 UUID API가 없는 Jest 환경에는 테스트용 UUID를 주입했다. 실패 후 같은 request ID로 재시도하는 동작을 검증했다.
- 공개 확정 단계에서 `재개할 대화가 없습니다`가 발생했다. 선택 적용 API가 terminal checkpoint에서 제안을 만들었는데 UI가 `/chat/resume`을 사용한 것이 원인이다. [LangGraph checkpoint 재개 문서](https://docs.langchain.com/oss/python/langgraph/use-time-travel)의 terminal checkpoint 동작을 확인하고, 기존 proposal 확인 API로 직접 확정·취소하며 checkpoint를 동기화했다. 새로고침 후에도 동일한 확인 경로를 사용하도록 회귀 테스트를 추가했다.

## 공개 환경 검증 (2026-10-13)

`b872bc5` 배포 후 별도 합성 계정으로 사용자가 제공한 문장을 검증했다. 밥 200g·삼겹살 200g·라이스페이퍼 80g은 추가 질문 없이 계산됐고, 돼지바에는 버튼만 표시됐다. 직접 입력 폼은 기입하기를 누른 뒤에만 열렸다.

- 일반 아이스크림 기준을 명시적으로 선택한 뒤 확인 전 DB 기록 0개, 확정 후 4개·1657.3kcal. 새로고침 후 4개 유지, 중복 저장 없음.
- 별도 `밥 한공기 돼지바` 요청에서 돼지바 제외를 선택하면 밥 292kcal만 제안하며 제외 표시. 확인 전 기존 4개 유지, 확정 후 밥 1개만 추가되어 5개.
- 돼지바만 요청한 뒤 전체 취소하면 기존 5개 유지. 추가 입력 없이 취소 가능.
