# 일상 음식 범주 확대 — 2026-10-13

추가 질문을 줄이기 위해 기존 기본 분량 경로를 35개에서 53개 매핑으로 확대했다. 영양값은 기존 CSV 조회와 서버 계산을 사용하며 LLM이 생성하지 않는다. 마지막 확인 카드에서 분량 수정·취소 후 사용자가 확정해야 저장한다. 정확한 제품 찾기는 보조 기능으로 유지한다.

모두 편집 가능한 앱 정책값이며 보편적 실측 분량이라는 주장이 아니다. 피자는 1조각 100g·1판 800g, 만두는 개수와 1회분 150g을 구분한다. 직접 g 입력이 우선한다. `피자 반판`, `물만두 8개`, `군만두 3개`는 각각 400g·120g·90g이다.

`소보루`, `멜론`, `크로와상`, `군만듀`, `만듀`, `머겅써`, `먹엇어`, `메론빵으 ㄹ먹었어`, `냉동피자르 먹었어`를 처리한다. 등록되지 않은 모든 오타를 무조건 수정하지 않으며, 다른 제품의 접두부만 읽어 일부 음식으로 저장하지 않는다. 대표값 없는 항목의 기입·제외·취소는 기존 버튼 흐름을 유지한다.

## 정확성 표시와 실패 해결

- CSV에 메론빵 자체 항목이 없어 소보로 유사 기준을 정책으로 지정하고 카드에 명시했다. [Pasco 공식 영양표](https://www.pasconet.co.jp/nutrition/?action=nourish_list&p=1&sort_type=1)처럼 메론빵 제품마다 영양값이 다르므로 특정 제품값으로 주장하지 않는다. 외부 영양 수치를 DB에 새로 가져온 것은 아니다.
- [도미노 공식 제품 페이지](https://web.dominos.co.kr/goods/list?dsp_ctgr=C0101)는 메뉴별 영양정보를 구분한다. 브랜드명만 입력한 경우에는 메뉴를 다시 묻지 않고 일반 피자 대략값을 표시한다.
- 초기 테스트 13건 실패: 미등록 별칭, 목적격 조사·오타, 조각/판 단위 지원 누락. [Python 정규식 문서](https://docs.python.org/3/library/re.html)의 대안·문자열 끝 경계 규칙을 확인하고 제한된 별칭과 문장 끝 표현을 보강했다.
- 수정 API 테스트 3건 실패: 판 단위 거부와 만두 회분을 개당 중량으로 계산. 서버 소유 proposal의 단위별 g 설정을 그대로 재사용해 수정 계산과 최초 계산을 통일했다. 사용자 소유권·버전 검증은 유지한다.
- UI 테스트 1건 실패: 대략값 안내가 표시되지 않음. [React 조건부 렌더링 문서](https://react.dev/learn/conditional-rendering)에 따라 확인 카드에 기준 안내를 표시하고 수정 단위를 서버 metadata에서 읽는다.
- 전체 회귀 1건 실패: 기존 테스트가 피자를 미등록으로 가정. 미등록 제품 검증을 다른 미등록 이름으로 유지하고 피자 1조각의 정상 계산 검증을 함께 추가했다. 테스트 삭제나 추가 skip은 없다.
