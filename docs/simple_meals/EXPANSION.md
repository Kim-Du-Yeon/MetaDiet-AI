기준일: 2026-10-13. 기능 커밋 `3d38954`. 합성 검증이며 실제 사용자 성과와 구분한다.

## 변경

간단 입력 매핑을 12개에서 **35개**로 확장했다(조리 형태 포함). 이 중 34개는 기존 CSV의 유일한 정확한 항목, 1개는 이전에 검증한 식약처 라이스페이퍼 대표 기준이다. 제조사나 브랜드를 임의로 붙이지 않는다. 기본 분량은 앱의 편의 가정이며 보편적인 실측 분량이나 섭취 권고가 아니다.

등록 오타: 달각슴살·닭가슴샬·닭가슴삶·고구먀·브로컬리·요거뜨. 띄어쓰기 별칭, 계란후라이/프라이, 요구르트/요거트 등을 처리한다. 한·두·세·네·다섯·여섯·반과 숫자 분량을 지원하고 g가 명시되면 우선한다. 음식 사이의 랑·이랑·와·과·하고를 처리한다.

우유 한컵은 **앱 기준 200g**이다. mL를 임의로 g와 동일시하지 않으며 `200ml`는 기존 확인 흐름으로 보낸다. 오트밀은 건조 기준, 기본 계란은 삶은 것, 프라이는 별도 조리 항목, 기본 고구마는 찐 것·군고구마는 별도 항목이다. 사용자가 카드의 g·분량을 수정할 수 있다.

## 검증 및 실패 해결

- 초기 확장 입력 테스트: 9 failed / 21 passed. 로그에서 음식 미등록·붙여 쓴 별칭·연결 조사 때문에 전체 파싱이 None이 되는 것을 확인했다. 영양값을 채우는 방식으로 우회하지 않고 검토한 음식·문법만 추가했다.
- 짧은 `계란`이 긴 `계란후라이`를 먼저 소비할 수 있는 충돌을 확인해 긴 별칭 우선으로 정렬했다. [Python 정규식 문서](https://docs.python.org/3/library/re.html)의 왼쪽부터 매칭하는 동작을 참고해 순서를 명시했고 실제 CSV 프라이 항목으로 연결되는 테스트를 추가했다.
- [식약처 기준량 안내](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=bbs423&menu_grp=MENU_NEW03&menu_no=3717)에 따라 영양값의 100g 기준과 앱의 1회 분량을 분리했다. 기본 분량을 공식 권장량으로 제시하지 않는다.
- 고정 확장 요청 9개: 기존 d7f902a의 단순 파서 지원 0/9 → 확장 후 9/9. 현재 9개 모두 제안 생성, 기대 g 일치, 모델 0회·논리 도구 2회. 이전 Agent가 실패했다는 뜻이 아니라 **모델 없는 간단 경로의 지원 범위 비교**다.
- 미등록 제품/음식·알 수 없는 단위·음수·추천 요청 7개는 빠른 경로에서 배제했다. 알려진 음식만 일부 저장하지 않는다.
- 전체 34개 CSV 매핑의 유일한 항목·완전한 영양값을 검증했다. 프론트·HITL·proposal 수정 규칙은 유지했다.
- 전체 백엔드 **484 passed, 1 existing skipped**, 프론트 **65 passed**, production build 통과. 새 skip·테스트 삭제 없음.
