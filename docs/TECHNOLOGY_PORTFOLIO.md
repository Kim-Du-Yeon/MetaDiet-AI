# MetaDiet AI 기술 구현·실험·운영 적용 정리

작성일: 2026-10-20. 저장된 실행 보고서와 배포 검증 기록을 정리한 문서이며, 새 성능 실험을 실행한 결과는 아니다. 구현은 실행 가능한 코드, 비교 실험은 조건을 바꿔 측정한 결과, 운영 적용은 공개 서비스에 반영한 범위를 뜻한다. 로컬 kind 검증은 공개 Kubernetes 운영과 구분한다.

동일 합성 100개 사례를 조건별 1회씩 수행했다. 실패·타임아웃도 분모에 포함한다. 추출·분류·번역·후속 코칭 각 25건이며 일부 휴리스틱 분류는 모델 호출이 없다.

### Jev 모델 선택

규칙과 Jev 각각 100건에서 선택 처리 중앙값은 0.040→559.231ms, p95는 0.067→792.422ms였다. 개발자 선호 등급 일치는 60/100→97/100이지만 Jev 43건은 낮은 신뢰도로 표준 모델에 폴백했다. 이는 답변 정확도 개선이 아니다. 해당 실험 당시 생성·평가 quota 제한으로 Jev 선택 이후 전체 답변 품질·최신 실제 기록·전체 비용은 검증하지 못했다. 운영에는 규칙 라우팅을 채택했다. [원본 200건과 재현 방법](model_routing/JEV_COMPARISON.md)

### 최종 RAG 근거 평가

선정 이후 별도 동결한 **20문항 / 10개 한·영 사실 그룹**에서 20/20 완료, 지정 페이지 Recall@4 85%, 대체 유효 근거 포함 support 95%, Ragas faithfulness 1.00 / context recall 0.95였다. 원문 검토 정답률은 95%이며 비맹검 사후 검토다. 영어 질문 1건의 실제 근거 누락에는 답변을 보류했다.

이는 조건별 100건 실험이 아니며, 적은 표본의 과거 독립 최종 평가다. Ragas FactualCorrectness 진단값은 원문과 맞는 답변에도 낮은 점수를 주어 서비스 정답률로 채택하지 않았다. 평가자 점수와 원문 검토를 함께 공개한다. [최종 평가·오류 사례·평가자 한계](rag_experiments/RAG_FINAL_EVALUATION_V1.md)

### Kubernetes 복구

로컬 kind rolling restart 중 health 400/400 성공, p95 5.86ms를 관측했다. 이는 경량 health이며 AI 상담 응답 시간이 아니다. 별도 합성 SSE 실행 중 담당 Pod를 삭제한 뒤 다른 Pod에서 같은 run ID와 Postgres checkpoint로 재개했다. 승인 전 meal 0건·pending proposal 1건, 같은 제안 두 번 승인 후 meal 1건으로 중복 저장 방지를 확인했다. 이 장애 복구 사례를 100건 실패율 평가로 해석하지 않는다. ## 시행착오와 설계 판단

- Docling native 오류는 로그를 통해 분리·격리하고 복구 경로를 실험했다. 최종 선택은 표 표현만이 아니라 처리 안정성과 검색 품질을 함께 고려했다.
- FlashRank를 포함한 API·BM25·Kiwi·모델 런타임 조합이 1GiB Pod 예산을 초과했다. 품질 개선도 없어 리랭커를 제거했다. Kubernetes 자체 결함으로 설명하지 않는다.
- 모든 요청에 RAG와 전문 Agent 위임을 강제하면 비용·지연이 증가한다. 일반 추천은 확인된 기록으로 답하고 근거가 필요한 상담은 검색 가능한 경로로 처리한다. 실제 사용된 문서만 출처로 표시한다. [질문·실행 단계·출처 원본 캡처](food_catalog/selective-rag-20261019/README.md)
- 모델 라우팅은 새로운 모델을 모든 작업에 적용하지 않고 검증한 작업에만 제한 적용했다. 프롬프트 v1을 고정해 모델 변경 효과와 프롬프트 변경 효과를 섞지 않았다. [프롬프트 버저닝 범위](prompt_versioning/README.md)
