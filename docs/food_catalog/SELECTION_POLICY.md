# 일반 음식 표준값과 제품 선택 카드 (2026-10-13)

## 구현

- 기존 CSV의 일반 음식 표준값을 우선한다. 검증한 별칭인 쌀밥, 삼겹살구이, 고등어구이는 각각 백미 밥, 팬에 구운 삼겹살, 구운 고등어로 조회한다. 일반 음식에도 실제 조리법 차이가 있음을 표시한다.
- 제조사 제품은 MFDS에서 조회하며 후보가 하나여도 사용자가 선택한다. 명시적 product 조회는 일반 음식 별칭을 우회한다.
- 제품 확인은 제조사·제품명·용량 카드와 섭취량 입력으로 수행한다. 내부 식품 ID를 사용자에게 입력시키지 않는다. 선택 요청에는 원래 전체 식사와 날짜를 보존한다.
- 선택은 저장이 아니다. Agent 재검토 → 기존 proposal → 사용자 확정 경계를 유지한다. 미선택·미등록 항목을 제외한 부분 식사 제안은 차단한다.
- 출처는 삭제하지 않고 확인 카드의 펼쳐보기로 이동한다. 선택 카드 상태는 체크포인트와 화면 복원 응답에 포함한다.
- 기존 체크아웃을 재사용하고 기존 임시 디렉터리는 보존했다. 새 데이터 수입·스키마 변경은 없다.

## 실패와 수정

1. 초기 실제 Agent 검증에서 라이스페이퍼가 미등록으로 분류됐다. 동일 DB 직접 조회에는 MFDS 후보가 존재했다. 모델이 standard로 지정해 제품 조회가 차단된 것이 원인이었다. 표준 검색이 비면 서버가 auto 조회를 한 번 수행하고 제품 후보는 카드로 확인하도록 수정했다. [공식 도구 입력·설명 문서](https://docs.langchain.com/oss/python/langchain/tools)를 참고했다. 모델의 분류를 DB 존재 여부로 취급하지 않는다.
2. 별도 코드 검토에서 단일 일반 음식 후보 확인 차단과 동일 제품 중복 선택 거부를 발견했다. Agent는 단일 표준 후보를 계산하고, 동등한 후보 카드 중복을 제거했다. 복수 일반 음식 후보는 조리 형태를 확인한다. 기존 공개 API의 부분 일치 선택 정책은 호환성을 위해 유지했다.
3. Python 사전 선언 SyntaxError와 조건부 local import의 UnboundLocalError를 로그로 확인하고 각각 사전 unpack 및 함수 시작 import로 수정했다. [사전 문법](https://docs.python.org/3/reference/expressions.html#dictionary-displays), [지역 변수 규칙](https://docs.python.org/3/faq/programming.html#why-am-i-getting-an-unboundlocalerror-when-the-variable-has-a-value).

## 한계

모든 일반 음식 이름을 임의로 하나로 합치지 않는다. 조리 형태가 불명확한 복수 표준 후보는 추가 질문한다. 브랜드를 찾지 못하면 영양표를 요청하며 다른 제품으로 대체하지 않는다. 카드 상태 복원은 자동 저장이나 완료 실행 재수행을 의미하지 않는다.


실제 Gemini 합성 요청에서는 일반 음식 3개·제품 카드 1개·최종 확인 제안 4개를 검증했다. 첫 검토 4회 모델/8회 도구/34.969초, 제품 선택 후 5회 모델/9회 도구/32.985초였다. 단일 사례이므로 중앙값이나 p95·속도 향상으로 표현하지 않는다. [원본 결과](SELECTION_POLICY_LIVE.json). 공개 API에서도 쌀밥·삼겹살구이·고등어구이는 CSV found, 라이스페이퍼는 ambiguous 후보로 확인했다.

공개 브라우저에서 요청하지 않은 월남쌈 제품 후보 추가를 관찰했다. 제품 검색어가 사용자 요청에 포함되는지 서버가 검증하도록 보완하고 미요청 후보 차단 재현 테스트를 추가했다. 모델이 만든 동의어를 자동 제품 대체로 허용하지 않는다.
