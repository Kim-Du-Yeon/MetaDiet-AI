# 일반 음식 대표 연결 보강과 동일 100종 재검증

2026-10-16. 기존 LangGraph·proposal·HITL·중복 방지를 유지했다. 새 DB 마이그레이션이나 외부 검색 의존성은 추가하지 않았다.

## 구현

- `common_representatives.json`에 **47개 대표 연결·106개 입력 표현**을 모았다. 공식 일반 조리 음식 40개 ID/100g 영양값/기준일/URL과 CSV 7개 연결을 사용한다. 기존 기본값 목록과 음식군 규칙은 유지하고 검토된 연결이 우선한다. [공식 출처·선택 근거·원페이지 해시](COMMON_REPRESENTATIVES_SOURCE.json).
- 국·찌개·볶음·구이·반찬·밥류·과일·음료를 보강했다. 계란/달걀, 쭈꾸미/주꾸미, 돈까스/돈가스 등 별칭을 처리하고 김밥 ‘줄’, 국·찌개 ‘그릇’도 지원한다.
- 음식마다 앱 기본 1인분을 채우며 명시 g를 우선한다. 예: 잡곡밥 200g, 김밥 250g, 된장찌개 200g, 미역국 300g, 소갈비찜 200g. 이 분량은 **공식 보편 1인분 주장 없이 수정 가능한 앱 기본값**이다.
- 김치볶음밥→새우볶음밥, 크림스파게티→미트소스 대체를 해당 공식 요리로 수정했다. 일반 볶음밥/파스타 음식군도 특정 새우·미트소스 대신 일반 대표값을 사용한다.
- 청국장 별칭이 같은 이름의 원재료보다 청국장찌개를 우선하도록 조회 순서를 수정했다. 수육은 탕수육이 아닌 삶은 돼지고기, 참치회는 참치회덮밥 양념장이 아닌 참다랑어 붉은살로 연결했다.
- 식약처 출처 자체를 ‘브랜드 제품’으로 보던 Agent 경로를 `food_kind`에 따라 구분했다. 검토된 일반 조리 음식은 제조사 선택을 요구하지 않고, 실제 제품의 기존 선택 경계는 유지한다.
- 사용자 입력명과 적용 대표값·근사 안내를 보존한다. 확인 전에는 pending proposal만 생성하며, 수정·제외·취소·확정은 기존 API를 사용한다. 기존 김치찌개 제품 ID는 과거 기록 호환성을 위해 유지하고 신규 일반 입력만 일반 조리 음식 ID로 전환했다.

## 동일한 100종, 전후 각 100회

[동결 입력](COMMON_FOODS_100.json), [수정 전 원결과](COMMON_FOODS_100_RESULTS.json), [수정 후 원결과·실행 소스 해시](COMMON_FOODS_100_AFTER.json), [요약 JSON](COMMON_FOODS_100_COMPARISON.json).

## 크레딧 문제는 별도 미해결

수정 후 최소 모델 호출도 `402 RESOURCE_EXHAUSTED: Your prepayment credits are depleted.`로 실패했다. [Google 공식 결제 설명](https://ai.google.dev/gemini-api/docs/billing#prepay)에 따라 잔액 복구가 필요한 외부 조건이다. 결제·키 교체는 실행하지 않았다. 이번 100종은 모델을 거치지 않아서 성공한 것이며 모델 서비스가 복구된 것은 아니다. 낯선 표현, 복잡한 문장과 코칭 등 모델 경로는 여전히 영향을 받을 수 있다. 로컬 키와 배포 키의 계정 동일성은 확인하지 않았다.

## 실패 원인과 재검증

1. 추가 회귀를 먼저 실행해 기본 연결 누락과 잘못된 대체 **54 failed /57 passed**를 재현했다. 대표 연결을 추가한 뒤 같은 테스트가 통과했다.
2. 공식 사이트 검색은 페이지 크기100에서 `dataList`가 없어 실패했다. 공식 UI와 동일한20건 조회로 후보를 확인하고, 검토한 고정 ID의 상세 페이지에서 100g 기준값과 기준일을 추출했다. 검색 첫 결과를 자동 채택하지 않았다. 상세 영양 추출은 추가 패키지 없이 수행했다.
3. 기존 회귀6건은 새 공식 출처를 이전 CSV/제품 기준일로 기대하던 assertion이었다. 공식 ID·기준일·일반 음식 분류를 명시적으로 검증하도록 갱신했다. 테스트 삭제·skip은 하지 않았다.
4. 별도 회귀로 일반 MFDS 음식의 제품 선택 오인, 청국장 원재료 우선 충돌을 재현하고 수정했다. 독립 코드 리뷰에서 띄어 쓴 김치 찌개만 옛 제조사 제품으로 연결되는 누락을 발견해 실패 테스트 재현 후 같은 일반 ID로 통일했다. 실제 제품의 임의 확정 방지 회귀도 유지했다.
5. 프론트 테스트는92개 assertion이 끝난 뒤 `ENOSPC` 캐시 쓰기로 exit1이 발생했다. [Jest 공식 cacheDirectory](https://jestjs.io/docs/configuration#cachedirectory-string)에 따라 D드라이브 캐시로 재실행했다. 그때 대량 UI100회 갱신 테스트가 기본5초를 초과했다. [Jest 공식 timeout](https://jestjs.io/docs/api#testname-fn-timeout)에 따라 CLI 대기 한도를15초로 지정해 동일 전체92개를 다시 실행하고 exit0을 확인했다. 제품 코드나 테스트를 제거/skip하지 않았으며 이 실행은 속도 비교가 아니다.

## 검증과 한계

- 프론트 전체26 suites /92 tests 통과(exit0), 배포 빌드 통과. 테스트 환경 캐시·대기 한도 조정은 위에 공개했다.
- 백엔드 전체 **1337 passed /기존1 skipped** (exit0). 100종 외에 분량·혼합 문장·조회 경로·제품 승인 경계 회귀를 포함한다. 새 테스트를 skip하거나 기존 테스트를 제거하지 않았다.
- 고정 100종에 맞춰 보완한 개발 평가다. 임의의 모든 음식/오타/복합 문장까지100% 보장하지 않는다. 별도 미공개 음식 홀드아웃과 실제 사용자 피드백이 후속 검증이다.
- 근사 음식군은 남아 있다. 메론빵→소보로 계열 빵, 치즈버거→일반 햄버거, 돼지바→일반 아이스크림은 사용자 입력명을 유지하고 대표 기준임을 표시하는 근사이며, 해당 제품의 정확한 영양값이 아니다. 이를 ‘잘못된 제품을 정확히 조회했다’고 보고하지 않는다.
- 순두부찌개는 김치가 든 일반 대표값, 갈비찜은 소갈비찜, 샐러드는 드레싱이 포함될 수 있는 채소 샐러드 기준이다. 카드의 근사 안내를 유지하고 사용자가 바꿀 수 있다.
- 운영 섭취 기록은 변경하지 않았다. 이번100회는 메모리 proposal 평가이며 공개 브라우저100회 검증을 주장하지 않는다.
