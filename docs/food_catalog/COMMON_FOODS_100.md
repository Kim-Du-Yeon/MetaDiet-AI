## 원인 분리

### 1. 외부 모델 호출 중단 — 확인된 실행 장애

43개 모두 기본 분량 파서가 처리하지 못해 모델 경로로 넘어갔고 `ChatGoogleGenerativeAIError`로 종료했다. 별도 최소 모델 호출에서도 `402 RESOURCE_EXHAUSTED: Your prepayment credits are depleted.`가 재현됐다. [Google 공식 결제 문서](https://ai.google.dev/gemini-api/docs/billing#prepay)는 선불 잔액 소진 시 402로 요청이 중단됨을 설명한다.

이 장애는 재시도·검색 추가로 해결되지 않는다. 해당 프로젝트의 사용 가능한 잔액 복구가 외부 조건이다. 결제나 API 키 변경은 실행하지 않았다. 로컬 키의 계정이 공개 배포와 동일한지는 검증하지 않았으므로 공개 서비스 전체가 중단됐다고 단정하지 않는다. 잔액 복구 후 같은 동결 100개를 다시 실행하고, 최초 결과도 보존해야 한다.

### 2. 일반 음식 자동 경로의 범위 부족 — 코드로 확인

`simple_meals.py`의 명시 별칭·대표 항목·분량 표와 `food_groups.py`의 18개 음식군 규칙이 전체 문장을 처리해야 모델 없이 카드가 나온다. 이번 100개 중 이 경로에 연결된 것은 57개이며 나머지 43개는 모델에 의존한다. 국·찌개 10개 중 1개, 생선·해산물 10개 중 1개만 자동 경로를 탔다. 일반 음식 전반이 충분히 연결됐다고 볼 수 없다.

CSV에 포도·수박·배·복숭아·키위·삶은 수육 항목이 있어도 사용자 표현과 대표 항목/기본 분량의 연결이 없으면 자동 경로를 타지 못한다. 반면 CSV에 `미역국` 같은 문자열이 없다고 전체 공식 DB에 음식이 없다고 결론 내릴 수 없다. 조리 음식 D 계열과 가공 제품 P 계열의 범위를 구분해 확보해야 한다. 부분 문자열 검색은 ‘김밥→김밥용 김’, ‘청국장→재료 청국장’ 같은 잘못된 결과를 줄 수 있다.

### 3. 카드 생성과 대표값 적절성은 별도

- 김치볶음밥이 새우볶음밥으로 연결됐다. 볶음밥이라는 이유만으로 재료가 다른 구체 음식을 선택하는 규칙이다.
- 메론빵은 소보로빵, 치즈버거는 일반 햄버거, 돼지바는 바닐라 아이스크림 대표값이다. 기본값 사용을 원한 제품 UX와 맞더라도 ‘정확한 제품 영양값’이라고 표시하면 안 된다.
- 따라서 **57개 카드 생성 = 57개 정확한 음식 판정**이 아니다. 이 실험은 외부 영양표 골드와의 수치 오차를 평가하지 않았다.

## 제안하는 해결 순서

1. **일반 음식 대표 레지스트리를 데이터로 관리한다.** 공식 일반 조리 음식/CSV의 안정적인 ID, 표시명, 별칭, 기본 1인분 g, 근사 수준, 출처·검토일을 묶는다. 과일·생선은 기존 CSV 연결을 우선하고 국·찌개·덮밥은 공식 조리 음식 대표값을 보강한다. 사용자 음식명을 원재료·가공 제조사 목록으로 연결하지 않는다.
2. **일반 음식 처리에서 모델 의존을 줄인다.** 음식 표현 → 대표 항목/음식군 → 명시 g 또는 기본 1인분 → 서버 계산 → 확인 카드로 연결한다. 모델은 낯선 표현/복합 문장 해석에만 사용하며 영양값을 만들지 않는다. 기본 분량은 앱 기준으로 표시하고 수정·제외·취소를 유지한다.
3. **음식군 대체의 경계를 검토한다.** 김치볶음밥을 새우볶음밥처럼 특정 다른 요리로 표시하는 연결을 제거하고, 실제 검토된 일반 대표값 또는 해당 요리 대표값으로 연결한다. 브랜드명은 사용자 표시명으로 유지하되 근사 대표 기준을 함께 표시한다.
4. **정말 대응할 근거가 없는 항목만 선택권을 준다.** 영양표 기입은 보조 기능으로 두고 제외·전체 취소를 제공한다. 근거가 없는 수치를 만들거나 조용히 일부 음식만 합계에 넣지 않는다. Exa를 매 요청마다 호출하는 방식보다 공식 대표 데이터와 별칭 연결을 먼저 보완한다.
5. **동결 100종 전후 재평가 + 별도 혼합 문장 회귀**를 수행한다. 외부 모델 잔액 문제를 먼저 해소하고, 100종 자동 카드율·수동 선택율·오류율을 모두 보고한다. 기본 g/명시 g 보존/대표 ID 적절성/미저장/수정·제외·취소도 따로 판정한다. 새 음식의 별도 홀드아웃셋을 추가해 이 100개 이름만 맞춘 과적합을 막는다.

이번 작업은 평가 도구·결과·진단을 추가했다. 실제 음식 연결이나 공개 배포 동작은 변경하지 않았다. 후속 구현 완료/개선 성공을 주장하지 않는다.
