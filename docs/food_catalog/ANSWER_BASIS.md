# 답변의 참고 기록·근거 표시

2026-10-19 공개 배포·실제 모델/브라우저 검증 완료. [검증 결과·실패 수정·캡처](answer-basis-20261019/README.md).

## 표시 범위

답변 아래 접힌 ‘참고한 기록·근거’에 요청 중 조회한 확정 식사 목록, 섭취 합계와 활성 목표, 조회한 식품 계산 출처, 명시적 문서 인용과 한계를 표시한다. 개인정보나 내부 사용자 ID는 전달하지 않는다. 기록 수치는 답변 작성 당시 스냅샷이며 미기록 식사를 추정하지 않는다.

검색 도구는 모델에 evidence_id 인용 형식을 안내한다. 서버는 해당 요청에서 검색한 자료 중 답변이 명시적으로 인용한 ID만 문서명·페이지·URL·발췌문으로 연결한다. 알 수 없는 ID는 출처로 채택하지 않는다. 검색됐다는 이유만으로 문서를 인용 목록에 넣지 않는다. URL은 화면에서 http/https만 허용한다. 인용 자체는 주장 타당성의 자동 검증이 아니다.

문서 검색 미수행·근거 확보 실패·검색했지만 인용 미확인을 구분한다. meal/supervisor 내부 경로 표시는 식단 추천/종합 상담으로 번역했다.

## 보존과 한계

기존 소유자·thread 범위 체크포인트에 근거 메타데이터를 함께 보관하고, 최신 복구 답변의 내용이 일치할 때만 연결한다. 과거 모든 메시지의 영구적인 근거 이력 저장은 이번 범위에 포함되지 않는다. 레거시 답변에 근거를 소급 생성하지 않는다. 다른 기기나 기록 변경 후에도 과거 답변의 근거는 작성 당시 수치다.

일반 Team 코칭 경로에 연결했다. 별도 레거시 노드 등 메타데이터를 생산하지 않는 경로에는 근거 상자를 생성하지 않는다. 모델 인용 누락은 한계로 표시하며, 실제 모델 인용 품질·각 문장의 근거 적합성은 별도 평가가 필요하다. 식품 계산 항목은 이번 요청의 서버 조회 내역으로, 해당 값 모두가 최종 답변에 사용됐다고 보장하지 않는다.

## 기업용 챗봇 사례를 반영한 출처 UI

Microsoft Copilot의 [공식 출처 표시 안내](https://support.microsoft.com/en-us/microsoft-365-copilot/control-review-sources-copilot-chat)는 문장 인용, 하단 Sources 버튼, 출처 목록과 원문 열기를 제공한다. Google Cloud [Answer API 문서](https://docs.cloud.google.com/generative-ai-app-builder/docs/answer)도 답변의 citation metadata를 별도로 반환한다. 제품 UI와 API 기능은 구분해 참고했다.

현재 앱에는 ‘출처 보기 · N개’와 ‘내 기록·계산 근거 보기’를 별도 토글 버튼으로 제공한다. 출처는 번호·문서명·페이지를 먼저 표시하고, ‘인용 내용 보기’와 ‘원문 보기’를 제공한다. 모바일에서도 마우스 hover 없이 조작할 수 있고, 키보드 초점과 aria-expanded/controls로 펼침 상태를 알린다. 출처가 0개여도 검색 미수행 등의 설명을 확인할 수 있다. 원문 URL이 없는 경우 링크를 만들어내지 않는다. 답변 내 번호와 출처 카드 번호는 일치하지만 본문 번호 클릭 이동·PDF 페이지 미리보기는 아직 없다.

테스트 중 한계 문구 앞의 강조 요소 때문에 정확 문자열 검색이 실패했다. [Testing Library ByText 문서](https://testing-library.com/docs/queries/bytext/)의 TextMatch 규칙을 확인하고 문구를 식별하는 정규식으로 검증했다. 제품 문구나 테스트 항목을 삭제하지 않았다.

## 공개 검증에서 발견한 검색 금지 오분류

요청 ID 2663e7c8-222b-4ab9-8ffe-3f9ff087642e의 화면 실행 단계에는 전문 Agent 위임은 있었지만 근거 검색은 없었다. 출처 패널도 검색 미수행으로 표시했다. 요청의 ‘공식 지침에서 검색’과 뒤쪽 ‘식사 제안 생성 없이’를 기존 검색 금지 정규식이 하나로 매칭했다. 공개 응답은 검색 기능이 없다고 잘못 설명했다.

동일 문구와 ‘검색하고 기록은 변경하지 마’, ‘검색해서 알려줘. 저장하지 말고 설명만 해줘’를 단위 테스트로 재현했다. 최초 4 failed / 6 passed(별도 영어 금지 표현 미지원 포함). [Python re 공식 문서](https://docs.python.org/3/library/re.html)의 반복·문자열 매칭 동작을 확인하고, 검색 동작에 인접한 금지 구문으로 범위를 제한했다. 관련 정책·위임·코칭 테스트 38건 통과. 명시적 검색 금지는 계속 유지한다.

이 결과는 기능 재현과 회귀 검증이며 검색 품질이나 성공률 개선의 통계적 비교가 아니다.
