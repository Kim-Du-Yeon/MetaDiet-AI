# 소수 베타 사용자 테스트 시나리오

기준일: **2026-10-15** · 접속: [MetaDiet AI](https://metadiet-web.onrender.com) · [사용 안내와 피드백](BETA_USER_GUIDE.md)

10~15분 정도의 핵심 확인 순서입니다. 시간은 안내용 예상이며 응답 속도 측정 결과가 아닙니다. 전부 수행할 필요는 없고 막히면 건너뛰거나 중단해도 됩니다. **가상 식사는 확정하지 말고 취소**해주세요. 저장·새로고침 검증은 실제로 먹은 식사로만 진행합니다. 이미 저장한 식사를 또 기록하지 않습니다.

## 핵심 시나리오

| 번호 | 해볼 작업 | 확인할 모습 | 기록 영향 |
|---|---|---|---|
| B01 | 회원가입 → 이메일 인증 → 로그인 → 처음 한 번 기본 정보·목표 설정 | 로그인 후 해당 화면으로 진행되고 기존 사용자는 기존 설정을 읽음. 인증 링크가 localhost로 가거나 로딩에 멈추면 오류 신고 | 가입·설정 정보 저장 |
| B02 | 연습으로 `닭가슴살 밥 한공기 김치 먹었어` 입력 | 추가 g 질문·제조사 선택 없이 계산 카드. 앱 기본값 닭가슴살 100g, 밥 200g, 김치 40g. 음식별 열량·탄단지·합계 표시 | 확인 전 섭취 미저장 |
| B03 | B02 카드에서 닭가슴살을 2회분 또는 200g, 밥을 1.5공기 또는 300g으로 수정하고 **수정한 분량 다시 계산** | 적용 g와 음식별 영양·합계 갱신. 오늘 기록이며 목표가 있으면 기록 후 남는 칼로리도 갱신. 재계산 전에는 변경 전 수치라는 안내 | 확인 전 섭취 미저장 |
| B04 | 김치 **제외하기** → 다시 계산 → **취소** | 김치가 합계에서 빠지고, 취소한 식사는 캘린더에 새로 추가되지 않음 | 연습 종료, 섭취 미저장 |
| B05 | 다른 연습으로 `김치찌개 간장불고기 먹었어` 입력 후 취소 | 둘 다 앱 기본 200g/1인분 표시, 분량 수정 가능. 제조사 선택이나 빈 g 입력 화면으로 막히지 않음 | 취소, 섭취 미저장 |
| B06 | 아직 기록하지 않은 **실제 식사** 입력 → 카드의 날짜·끼니·음식·분량 확인 → 필요 시 수정/재계산 → **이대로 기록** 한 번 | 저장 성공 안내. 캘린더에서 해당 날짜·끼니에 한 번만 표시. 기존 다른 기록은 유지 | 실제 섭취 저장 |
| B07 | B06 이후 새로고침 → 캘린더 확인 → 로그아웃·같은 계정 재로그인 | 확정 기록이 유지되고 새로 저장하지 않아도 확인 가능. 다시 ‘이대로 기록’을 누를 필요 없음 | 기존 기록 조회 |
| B08 | 실제 기록 후 **점심 추천** 또는 **저녁 추천** → `한식뷔페에서 먹는다면?`처럼 후속 질문 | 저장된 섭취와 목표를 반영한 코칭. 식단 계획은 실제 섭취 합계에 자동 추가되지 않음. 불필요한 같은 질문·목표 표 반복도 관찰 | 코칭 대화 저장, 실제 섭취 미추가 |
| B09 | **설정 → 베타 피드백**에서 만족도·종류 선택 → 의견 없이 또는 한 줄 작성 → **피드백 보내기** | ‘피드백을 보내주셔서 감사합니다.’ 표시. 실패 시 입력 유지·재시도 가능 | 피드백 저장 |

식사 중량과 영양값은 앱 대표 기준의 대략값입니다. 임상적 정확성이나 제품별 성분 일치를 확인하는 시험이 아닙니다. B02/B05의 분량은 앱 기본값이며 모든 사람이 실제로 먹는 보편적 분량이라는 뜻은 아닙니다. 로그인·기록 등이 막히면 이후 단계는 미수행으로 남겨도 됩니다.

## 선택해서 확인할 항목

- **오타·개수:** `달각슴살 2개 밥 1.5공기 김치 먹었어` → 닭가슴살 200g·밥 300g 적용 여부 확인 후 취소합니다.
- **명시한 g 우선:** `김치찌개 300g 간장불고기 200g 먹었어` → 입력한 g 유지 여부 확인 후 취소합니다.
- **기준 없는 음식:** 직접 만난 항목에 기입·제외·취소 선택이 있는지 봅니다. 입력을 원하지 않으면 제외하거나 취소합니다. 이름을 모르는 음식을 일부러 만들어내거나 영양 수치를 지어내지 않습니다.
- **정확한 제품:** 원하는 사용자만 ‘제품을 정확히 입력’/‘제품 영양표 입력’을 사용합니다. 일반 음식 기록을 위해 이 기능을 수행할 필요는 없습니다. 포장 영양표를 직접 입력하는 경우에도 저장 전 확인합니다.
- **대시보드:** 가입 체중 표시, 체성분 없으면 ‘미입력’을 확인합니다. 실제 측정값을 기록하려는 경우에만 **측정 기록하기 → 체중만 기록** 등을 사용하고 확인 후 확정합니다. 베타 테스트 때문에 허위 건강 데이터를 만들지 않습니다.
- **휴대폰:** 카드·확정/취소 버튼이 잘리지 않는지, 스크롤·키보드 사용이 가능한지 봅니다.
- **느린 응답/오류:** 화면의 안내와 재시도를 확인합니다. 저장 성공 여부가 모호하면 캘린더부터 보고 같은 식사를 다시 확정하지 않습니다. 무한 로딩·버튼 비활성·기록 유실은 발생 시각과 함께 제보합니다.

계정 삭제나 기존 실제 기록 삭제는 이 시나리오에 포함하지 않습니다. 테스트 데이터를 정리한다며 다른 기록을 지우지 마세요.

## 가장 간단한 결과 남기기

**설정 → 베타 피드백**에서 점수와 종류만 골라도 됩니다. 의견을 적고 싶다면 아래 한 줄이면 충분합니다. 이메일·체중·대화 전문을 다시 적을 필요는 없습니다.

> B03 / 휴대폰 Chrome / 10월15일 저녁 / 밥 분량 수정 뒤 다시 계산 버튼이 계속 비활성화됐어요.

잘 됐던 점도 보낼 수 있습니다. 실패/중단/해당 없음은 구분해주세요. 별도의 체크박스 설문을 새로 구현한 것은 아니며 아래 표는 **선택적으로 복사할 기록 양식**입니다.

| 시나리오 | 결과: 성공 / 실패 / 중단 / 미수행 | 증상 한 줄(선택) |
|---|---|---|
| 예: B03 | 실패 | 수정 후 재계산 버튼 비활성 |

인앱 피드백 전송 자체가 실패하면 모집 담당자가 초대 때 안내한 비공개 채널을 사용합니다. 화면 캡처는 선택사항이며 인앱 파일 첨부 기능은 없습니다. 공유 전 이메일·신체 수치·다른 대화 등 개인정보를 가립니다. 공개 GitHub 이슈에는 비식별 오류만 남기고 비밀번호·인증 코드·토큰·건강정보를 올리지 않습니다.

## 운영자 집계와 재현

피드백은 [관리자 화면](ADMIN_FEEDBACK.md)에서 담당자·상태·이력을 관리합니다. 사용자가 시나리오 번호를 적지 않아도 접수하고, 질문을 추가해야 한다면 필요한 한 가지만 선택적으로 확인합니다. 완료 안내는 자동 발송되지 않으므로 별도 소통이 필요하면 합의된 채널로 진행합니다.

| 집계 항목 | 기록 기준 |
|---|---|
| 참여·응답 규모 | 초대 인원, 확인된 참여 인원, 피드백 응답 인원을 구분 |
| 기능 확인 | 시나리오별 확인된 시도·성공·실패·중단·미확인 수. 피드백이 없다고 성공으로 간주하지 않음 |
| 만족도 | 응답 수와 1~5점 분포. 전체 사용자의 평가나 건강 효과로 일반화하지 않음 |
| 개선 작업 | 비식별 증상, 재현 여부, 담당자, 상태, 이슈/커밋, 재검증 근거 |
| 성능 비교 | 동일 동결 사례로 조건별 최소 100회, 실패·timeout 포함. 소수 베타 관찰과 합성 평가를 분리 |

베타 진행 전에 이 문서를 채운 성공 사례는 없습니다. 실제 결과를 수집한 뒤에만 사용자 성과를 보고합니다. 현재 [개발 검증 결과](admin-feedback/RENDER_RECOVERY_VALIDATION.md)는 합성 1만 건·독립 Render 환경의 관리자 API 검증이며 베타 사용자의 경험·AI 답변 정확도·건강 효과와 다릅니다.
