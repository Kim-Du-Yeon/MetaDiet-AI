### v1/v2 비교

가설: 현재 확정량/목표가 없는 상황에서 ‘단백질·지방이 충분하다’는 단정을 v2의 명시적 규칙으로 줄인다. v2는 `team.compact_followup`만 변경했고 나머지7개는 같은 실제 LangSmith 커밋을 재사용했다.

| 지표 | v1 | v2 |
|---|---:|---:|
| 시도/정상 종료 | 100/100 | 100/100 |
| Pro 정확·충실 + 최신값·저장 차단 통합 통과 | 100/100 | 100/100 |
| 근거 없는 영양소 충분 판단 | 0 | 0 |
| 최신 칼로리/목표 반영 | 100/100 | 100/100 |
| 평균 지연 | 4.792초 | 4.646초 |
| p95 | 6.262초 | 5.996초 |
| 실패율 | 0% | 0% |
| 생성 토큰 기준 추정비용/100시도 | $0.123698 | $0.127800 |

Pro 쌍별 평가100호출로200답변을 채점했고 추정비용$0.555550. [원본200답변](comparison/paired.json) · [100쌍 평가](comparison/judges.json) · [요약/원본 해시](comparison/summary.json) · [동결 사례](comparison/frozen.json).

동일 Flash3.8/temperature0/low thinking/max1024, 실제 DietTeam 읽기 전용 후속 상담, 동일 합성 최신 조회, 검색 없는 경로, AB/BA 순서, 생성 동시성1. 수정·삭제·목표 변경·새 날짜의5상태×4질문형×5수치 변형이다. 독립100개 사용자 의도나 실제 사용자 성과가 아니다. 생성과 독립 평가가 일부 시간상 겹쳤고 양쪽 조건에 공통 적용됐다. 첫 토큰 지연은 invoke 경로여서 측정하지 않았다.

사전 기준은 품질2%p 이내 비열등·목표 오류 감소·최신값/무저장100%·p95/비용1.25배 이내·전체 채점/usage 완료. v2의 추가 규칙은 이 동결셋에서 효과를 입증하지 못했다. 결과를 본 뒤 기준이나 사례를 바꾸지 않고 v1을 선택했다. 현행 오류가 재현되지 않은 쉬운 셋의 ceiling effect가 있으며, 전체 영양 상담 품질100%를 뜻하지 않는다. 이 평가는 Ragas가 아닌 명시적 코칭 루브릭의 Pro 이진 판정이다.

### 캐시를 억지로 활성화하지 않은 이유

선택된v1을 고정한 뒤, 기존 통제 Hybrid100건의 실제 공개 검색 문맥과 새 비교의 저장된 합성 답변으로 제한된10메시지 이력100개를 검사했다. [원본 길이/해시/판단](cache-eligibility.json).

| 경로 | 검사 | 최대 토큰 | 4096토큰 충족 |
|---|---:|---:|---:|
| RAG 정확 문맥 포함 시스템 입력 | 100 | 4037 | 0 |
| 멀티턴 고정 구간·10메시지/각2000자 상한 유지 | 100 | 1714 | 0 |

CountTokens만 사용했고 캐시 생성·보관료·추가 답변 생성은 발생시키지 않았다. 입력을 늘려 실험을 강행하지 않았다. **명시적 캐시 전후100건 품질·TTFT·p95·총비용 비교는 미실시**다. 실제로 캐시를 쓴 것처럼 성능 향상 수치를 만들지 않는다. 위100건은 적용 가능성 검사이고 성능 비교가 아니다. 멀티턴 결과도 선택한 합성 이력의 결과이며 가능한 모든 최대 길이 대화를 대표하지 않는다.

개인 캐시 운영 훅/계정 삭제 연결·다중 워커 공유 lease·내구성 삭제 큐는 적용하지 않았다. 캐시 라이브러리의 모의 검증과 실제 개인 캐시 운영을 구분한다. 현재 서비스에는 개인정보를 캐시에 업로드하는 호출 경로가 없고 기능 플래그를OFF로 유지한다.

## 안전한 운영 제어

- 8개 프롬프트는 각각 비공개. 9번째 비공개 `metadiet-release-manifest`가 전체 실제 커밋/해시/변수/출력 계약을 고정한다. 원격 Runnable/모델/도구를 역직렬화하지 않는다.
- LangSmith 화면의 개별 프롬프트 수정은 초안이다. 검증·서명된 완전한 릴리스 명세만 Staging/Production으로 승격한다. 코드의 저장 승인·소유권·루프 제한은 프롬프트가 바꾸지 못한다.
- 60초 비동기 갱신/관리자 강제 갱신. 요청·진행 중HITL은 이전 스냅샷을 유지한다. 실패하면 마지막 정상 버전, 첫 부팅은 로컬v1. Render 교체 시 임시 파일이 보존된다고 가정하지 않는다.
- A/B 실제 배정은 별도 승인 전OFF. 프롬프트별 독립 태그를 운영에서 조합하지 않는다.
- 승인된v1의 메타데이터 전용 별칭 `v1-control-drill`은 동일한8개 커밋/문구로 승격·롤백을 점검하기 위한 것이다. 미통과v2를 운영에 넣는 실험이 아니다.

## 재실행
