### cb2-eval-missing_portion-04

질문: 먹은 두부덮밥의 실제 칼로리를 정확히 계산해줘. 얼마나 먹었는지는 아직 말하지 않았고 기본 1인분 추정은 이번엔 쓰지 마.

v3 원문:

> 정확한 칼로리 계산을 위해 드신 실제 분량과 조리 정보를 알려주세요.
>
> * 밥과 두부의 분량(g 또는 밥공기 기준 양)
> * 주요 조리 방식(두부를 부치거나 튀겼는지 여부, 기름 사용량)
> * 양념 종류(간장, 고추장, 굴소스, 전분물 사용 여부 등)
>
> 알려주시면 해당 정보를 바탕으로 정확한 영양 성분과 칼로리를 계산해 드리겠습니다.

Pro 이유: Answer asks for the required consumed amount but also makes unnecessary requests for detailed cooking methods and sauce types.

## 과거 판정과 새 판정을 섞지 않기

원래 v1/v2 결과는 정답98/96·충실성100/96·행동98/93이었다. 이번 공통 문맥 재채점은 정답99/98·충실성99/98·행동99/97이다. **기존 답변은 동일하므로 이 차이는 모델 개선이 아니다.** 평가자 문맥과 새 판정 호출의 차이다.

- known_intake-08·unlogged_meal-03: 실제 fixture에는 점심 행이 있었고 과거 judge에는 누락됐다. 새 판정은 두 답변을 지지했다.
- missing_portion-09·missing_choices-10: 답변을 재생성하지 않았는데 과거 실패→새 통과였다. 과거 가짜 UI·초점 질문 판정과의 불일치이며, 문맥 보강만의 효과라고 단정하지 않는다.
- missing_choices-03: 원래 v2가 통과했으나 새 judge는 선호 질문을 불필요하게 판정했다.

[과거 회귀6건과 새 판정 연결](main/original-regression-followup.json). LLM judge의 반복 판정 변동과 문맥 누락이 한계다. 원문·기존 점수는 보존했고 유리한 판정을 골라 합치지 않았다. 향후 사람 검토가 필요하더라도 원래100건의 기준을 소급 완화하지 않는다.

## 채택 판단

사전 기준 중 정답·충실성, 필수 질문, 근거 없는 확정0건, 최신값·무저장, 비용·p95 조건은 만족했다. 그러나 **전체 행동97<98·v1 99보다 낮음·v2 대비2건 회복 미달**, **전체 불필요 질문3>v1 0**으로 미통과다. 따라서 **운영 v1 유지, v3 서명·승격·배포·실제 사용자 A/B 미적용**으로 결정한다. 결과를 본 뒤 기준을 바꾸거나 본100건에 맞춰 추가 튜닝하지 않았다.

v3 두 프롬프트는 평가 전용 로컬 내용 해시이며 LangSmith 원격 커밋이 아니다. 향후 후보를 운영하려면 별도 개발셋에서 최소 질문과 계산 모드를 명확히 하고, 독립 holdout 및 두 프롬프트 릴리스 승인 연결을 확인해야 한다. 이번 완료 범위는 회귀 분석·개발 후보·동일100건 비교·미채택 판단이다.
