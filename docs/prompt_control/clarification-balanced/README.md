# 추가 질문 평가셋 — LangSmith 승격 전 품질 검증

2026-10-22 KST. **평가셋·오프라인 검사 완료 / 새100쌍 모델 비교 미실행 / Staging·운영 미적용.**

LangSmith 버저닝은 수정·커밋 선택·승격·복구를 제어하는 기능이며 이미 구현되어 있다. 이 작업은 그 기능을 다시 만드는 것이 아니라 **후속 상담 후보를 승격할 근거를 만드는 평가 작업**이다. 문구를 바꿨다는 이유만으로 운영에 적용하지 않는다.

## 어떤 경우에 묻고, 어떤 경우에는 바로 답하는가

| 필수 질문 | 실제 먹은 양 누락 | 정확한 실제 칼로리를 원하고 기본1인분 추정을 명시적으로 거부 |
| 필수 질문 | 조리 재료·양 누락 | 특정 집밥 한 냄비의 정확한 총 지방을 원하지만 레시피가 없음 |

**보통의 음식 기록/식사 선택에 무조건 분량을 묻도록 되돌리는 기준이 아니다.** ‘정확한 실제값이 필요하고 대표값 추정을 원치 않는다’는 대조 조건일 때만 필수 질문으로 분류했다. 없는 수치를 지어내지 않으면서 일반적으로 가능한 안내는 먼저 제공할 수 있다. 숫자를 모른다는 이유로 대화 전체를 보류하거나, 필요한 질문을 생략하고 침묵/포괄 거절하는 것은 성공이 아니다.

## 판정과 재사용 원칙

물음표가 있다는 이유만으로 오답 처리하지 않는다. 의미 기준은 `unnecessary_request`, `focused_required_question`, `unsafe_commitment`이며 질문 누락과 과잉 질문을 동시에 본다. correctness·faithfulness와 최신 수치·쓰기 없음도 별도로 확인한다. 사전 승격 기준은 불필요 요구50건 중 기존보다5건 이상 감소, 필수 질문48/50 이상·기존 대비1건 초과 악화 금지, 전체 correct+faithful98/100 이상·비열등성2pp, 최신값·쓰기 없음100%, 근거 없는 확정0건,100건씩 완전 채점, p95·비용1.25배 이내다. 개별 오류는100분모에서 제외하지 않는다.

오프라인 `clarification_cases.py`는 데이터 계약·요청 키·답변/rubric binding·분모를 검사한다. 같은 단어라도 맥락이 다르면 재사용하지 않는다. 입력/현재 기록/이전 대화/불변 프롬프트/모델/설정이 정확히 같은 답변만 재사용하며, 새 의미 rubric으로 바뀌면 기존 Pro39쌍 점수를 빌리지 않는다. 기존200출력은 보조 회귀 원본과 개발 예시로 보존하지만 **이 새100건의 답변으로 재분류하지 않았다.** 조건 요약의 `gate_passed`는 서명 승인 명세가 아니다. 새 평가용 실행 경로와 서명 어댑터를 검토하기 전 기존 승인 CLI가 임의 새 rubric을 수락하도록 풀지 않았다.

개발/평가 사례 ID·문장·품목은 분리했지만 같은10개 실패 유형에서 만든 합성 변형이다. 독립적으로 뽑은 실제 사용자100문항이나 임상적 유효성 검증이 아니다. 저장 출력에서 뽑은 개발 gold는1차 작성자 판단이며 독립 Pro 검토 결과가 아니다.

## Pro 차단 원인과 비용

이번 짧은 호출은 `GoogleRateLimitError`/`ClientError`, HTTP429와 `generativelanguage.googleapis.com/generate_requests_per_model_per_day`, `GenerateRequestsPerDayPerProjectPerModel`을 반환했다. 원문 오류·키·프로젝트 식별자는 저장하지 않고 허용한 metric/ID만 보존했다. 이 근거로 **일일 모델별 요청 한도**임을 확인했고 추가 호출하지 않았다. 정확한 수치/RPM/TPM/결제 계층은 이 오류로 모두 확인할 수 없다. 공식 설명상 한도는 프로젝트별로 공유하고 RPD는 태평양 자정에 초기화된다. [공식 한도 설명](https://ai.google.dev/gemini-api/docs/rate-limits).

짧은 실패 호출의 사용량은 확인되지 않아 보수적 예약 **$0.006186**을 유지했다. 현재 장부 **$8.735208**, 기존 원래 전체 상한$17.139139와 더 낮은 캠페인 상한$10.324354를 유지해 좁은 상한 잔여는 **$1.589146**이다. 비용을0으로 임의 정산하거나 장부를 초기화하지 않았다. 새 소규모 개발 smoke+최종200생성/100쌍 채점의 예상 추가비는 약$0.8~1.2지만 **지출하지 않았다.** 현재 comparison 단계 잔여는 약$0.263이며 development/browser 단계 잔여도0이므로, 재개 전 필요한 단계 예산을 동일 전체 상한 안에서 검토해야 한다. 오늘 단계별 상한은 변경하지 않았다. [공식 요금](https://ai.google.dev/gemini-api/docs/pricing).

## 남은 단계

1. Pro RPD 갱신 및 실제 프로젝트 한도 확인. 새 유료 가입/요금제 변경·다른 모델/프로젝트 우회는 하지 않는다.
2. 개발20건에서 gold/판정 기준과 실제 compact 경로 적용 범위를 검토한다. 최종100건으로 후보를 반복 튜닝하지 않는다.
3. 새 의미 평가 실행·불변 binding을 연결하고, 정확히 일치하는 입력의 저장 결과만 재사용한다. 같은 프롬프트·모델·설정의100건씩 비교를 끝내며 실패·미완료를 유지한다.
4. 새 suite의 승격 기준을 코드 검토한 서명 어댑터에 연결한다. 통과 전에는 기존 서명 게이트를 완화하지 않는다.
5. 기준 통과 때만 Staging 검증→Production 승격→공개 브라우저에서 실제 커밋/후속 대화/출처/최신 기록 확인. 실제 사용자 A/B는 계속OFF.

새 평가셋의 생성·채점이0건이므로 정확도/충실성/속도 개선을 보고하지 않는다. 운영 프롬프트와 데이터, 태그, 배포는 변경하지 않았다.
