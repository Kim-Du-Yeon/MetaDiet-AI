## 결론

**후보v2 미채택, 기존 signed v1 유지.** v2는 정답률·충실성·필수 질문 재현·지연·비용에서 우위를 보이지 않았다. 바로 답할 수 있는50건의 과잉 질문은 양쪽0으로 개선 목표의 바닥 효과도 확인했다. 후보를 통과시키기 위해 점수·분모·사전 기준을 바꾸거나 동일 답변을 유리한 판정이 나올 때까지 재호출하지 않았다. 기존v1 유지가 이번 새 코호트의 모든 안전 게이트를v1도 새로 통과했다는 뜻은 아니다.

평가자는같은Gemini3.1 Pro이며 원래 semantic rubric·gold·answer binding·AB/BA를 유지했다. 기존69개 유효grade object는 손대지 않았고, 나머지31쌍만 출력 지시를 평면14필드로 바꿔 채점했다. 따라서 모든100개가 완전히 동일한 judge system prompt였다고 표현하지 않는다.31개 새 결과는 실제system/request hash와 `clarification-grade-flat-v1`을 기록한다. 매pair에서v1/v2는 동일한 평가 조건을 받는다. 각 답변의 정확한 원문과 source hash로 추적할 수 있다.

## 출력 형식 문제는 어떻게 해결했는가

## 실패 사례와 채택 근거

- `known_intake-08` / `unlogged_meal-03`: 후보가 오늘 누적 섭취량을 특정 점심 섭취량으로 단정했다고 판정됐다. 수치는 같아도 기록의 적용 범위를 임의로 좁히는 문맥 충실성 문제다.
- `missing_choices-09` / `missing_choices-05`: 후보가 누락된 비교 선택지를 먼저 묻는 대신 대체 메뉴를 제시했다고 판정됐다.
- `missing_choices-03`: 기존 v1도 같은 종류의 필수 선택지 질문 누락이 있었다. 이 대조군은 변경하지 않은 supervisor 경로이므로 새 compact 프롬프트만의 회귀로 귀속하지 않는다.

목표군 50건에서 기존 v1의 과잉 질문이 0건이어서 사전 기준의 “5건 이상 감소”를 입증할 수 없었다. 이는 새 코호트의 바닥 효과다. 결과를 본 뒤 기준을 완화하지 않고 미채택으로 남겼다. 다음 후보를 만들려면 별도 개발셋이나 실제 관측 오류에서 문제 재현성을 먼저 확보하고, 누적 기록의 적용 범위와 필수 선택지 질문을 따로 개선해야 한다. 이번 동결 100건을 보고 수정한 뒤 같은 100건을 새 독립 검증처럼 반복하지 않는다.

실제 승인 CLI `approve_prompt_release.py evaluate`도 전체 원문에서 기준을 재계산한 뒤 **Candidate failed preregistered balanced gate**로 거부했다. [승인 검사 기록](complete100/approval-check.json). 서명 receipt·Staging/Production 승격·후보 배포·새 브라우저 검증은 없으며 실제 사용자 A/B는 OFF다. 기존 승인 v1이 현재 관측에서 더 나은 선택이므로 유지했다.
