# 선택적 마무리 제안 재발: v5 개발 검증

## 문제와 가설

v4 실제 Staging 점검의 `h5-stale-06`은 현재 합계733kcal·목표2129kcal에서 남은1396kcal를 올바르게 계산했지만 “추가로 식사를 기록하시거나 식단 추천이 필요하시면 편하게 말씀해 주세요.”를 덧붙였다. 계산 오류와 선택적 마무리 제안을 분리했다. 질문 금지 지시만으로는 물음표 없는 후속 유도문을 충분히 억제하지 못한다는 가설이다. 모델의 내부 원인이나 모든 재발 원인을 확정했다는 뜻은 아니다.

기존 v4 자료는 그대로 보존한다. 이 Staging 실행의 과거 LangSmith 조회 결과는0건이라 원래 로컬 실행 원문·커밋·usage만 근거로 삼으며, 과거 원격 trace가 있다고 주장하지 않는다. 새 실행부터 명시적 사례 trace를 추가했다.

## 변경 범위

`team.base`와 `team.compact_followup` 두 등록 텍스트 뒤에 종료 규칙만 추가했다. 현재 요청에 답했으면 끝내고, 사용자가 요청하지 않은 다음 상담·기록·추천 유도문은 물음표 유무와 무관하게 금지한다. 분량·개별 레시피·제품/영양표·선택지·지시 대상처럼 요청 결과에 꼭 필요한 누락 정보는 짧게 직접 묻도록 유지한다. 이미 제공한 값은 다시 묻지 않는다. 사용자가 명시적으로 요청한 다음 행동과 안전상 필요한 안내는 보존한다.

답변 후처리로 문장을 잘라내거나 모든 질문을 제거하지 않는다. 기존 LangGraph·모델 라우팅·HITL·소유권·저장 승인 코드와 나머지6개 텍스트는 변경하지 않았다. 후보는 비공개 LangSmith의 실제 불변 커밋으로 고정했다. 평가용 manifest는 서명·Production 승격과 구분한다.

## 비교 설계와 재사용

- 별도 합성 개발100사례 × v4/v5. 이미 알려진 재발1건 재현 + 새 질문문구99개이며, 외부 독립 holdout/실사용자 평가가 아니다.
- 바로 답변50건: 최신 합계·수정 목표·제공 영양표·일반 후속 상담·명시적 다음 행동. 필수 질문50건: 분량·레시피·제품표·선택지·지시 대상 각10건.
- 재발1건의 기존 v4 답변은 질문·대화·합성 현재값·8개 프롬프트·모델/설정의 request key를 검증해 재사용한다. 다른 과거 답변은 새 질문·새 후보에 맞지 않으므로 새 점수로 복사하지 않는다. 이전 실험100건/200답변은 원본으로 보존한다.
- 같은 Flash 모델·SDK·합성 기록·검색OFF·최대출력1024·low thinking·모델3/도구8 제한·65초 제한·동시성1·AB/BA 순서. 실제 supervisor와 compact 경로를 타며 평가 라벨로 경로를 강제하지 않는다.
- temperature=0은 양쪽에 동일하게 **요청한 설정**이다. Google 공식 문서의 Gemini3.6+ custom temperature 무시 제한을 고려해 결정적 생성이나 유효 temperature0을 주장하지 않는다.
- Pro Batch가 순서를 바꾼 두 답변을 같은 fixture truth로 채점한다. 기존 엄격한14개 boolean 출력 계약을 유지하고2쌍 형식 점검 후 나머지를 제출한다. 실패·타임아웃·채점 미완료는100분모에 남긴다.

## 먼저 고정한 후보 기준

후보100건 정상완료/채점/usage 연결, 정답·충실성 각각98 이상 및 기준선 대비 -1 이내, 행동98 이상 및 기준선 이상, 필수 질문50/50, 근거없는 확정0, 최신값/무저장100, 불필요 후속 요청2 이하이면서 기준선보다 감소, p95와 확인된 생성비용1.25배 이내. 기준선은100건 시도와 회계 연결이 필요하다. 기준선 실패를 후보 생성 실패로 혼동하지 않지만 비용·추적 불명확성을 통과로 취급하지 않는다. 사후 유리한 기준 변경으로 후보를 승격하지 않는다.

## 실행 중 회계 보강의 공개

첫29시도 이후 기준선 timeout을 그대로 보존한 채 회계/검증 코드를 보강했다. 반환되지 않은 usage를0으로 만들지 않고 실제 새 예약 ticket과 연결해 비용 범위를 표시한다. 비용 합격에는 기준선의 더 낮은 **반환 usage 확인액**만 사용해 실패가 후보에게 유리하게 작용하지 않도록 했다. 두 번째60번째 timeout은 usage와 새 ticket이 없어 비용 확정 불가로 남긴다. 원본 코드·protocol·60개 row와 변경 증명을 별도 보존했다.

실패한 다중 호출에서 일부 usage만 반환돼도 숫자 비용을 완전한 값으로 오인하지 않도록 추가 보강했다. 확인 비용을 하한으로 두고 전체 관련 예약액에서 그 값을 뺀 나머지만 상한에 더한다. 미확인 기준선 timeout은 보고서 작성에는 포함하되 엄격한 승인 검증은 거부한다. 이 회계/진행 변경은 실행 후 수정이며 새 사전등록으로 포장하지 않는다. 후보·질문·품질 기준은 변경하지 않았고 실패 사례는 재호출/대체하지 않았다.

## LangSmith 실사용 추적

새199요청은 `metadiet-v5-closing-offer-20261022` 프로젝트의 사례 root와 모델 child를 연결한다. metadata는 experiment_id·합성 case_id·조건·릴리스명·실제8개 commit ID/해시·모델/usage를 포함한다. 입력/출력은 LangSmith에서 숨기고, 검증용 합성 입력만 로컬 증거에 저장한다. 실제 사용자 ID·식사·목표·키는 새 metadata에 넣지 않는다.

![실제 LangSmith 사례와 모델 child, 사용 프롬프트 커밋](screenshots/langsmith-case.jpg)

화면의 evaluation 릴리스는 미승격 후보다. root8.64초와 model child2.52초처럼 계측 범위가 다르다. 답변 생성 지연은 기존 실행기 구간이며 root 생성/등록·종료 비용 전체나 공개 브라우저 지연과 같지 않다. 숨긴 본문을 원격 화면에서 확인했다고 주장하지 않는다. 원격 usage0/비용0인 미종료 child도 실제 무료 호출로 해석하지 않는다.
