## 판단과 후보 변경 (운영 미채택)

첫 호출은 답변 중복 생성이 아니라 위임 결정이다. 복합 요청에는 필요하지만 명확한 단순 추천에는 기존 직접 meal 경로를 재사용할 수 있다. 전체 문장 허용 목록에 `기록은 저장하지 말고 점심 메뉴 한 가지를 짧게 추천해줘`와 제한된 아침/저녁·하나만/간단히 변형을 추가했다. 알 수 없는 앞뒤 문장을 잘라내지 않는다. 원래 trace에 있었던 `원문 추적 확인용입니다.` 접두어는 여전히 Supervisor 경로다.

최신 문맥 확인, 요청별 예산, meal 프롬프트 릴리스, 읽기 전용 도구, 최종 답변 검증, HITL은 기존 구현을 재사용한다. pending proposal·확인 대기·requested_action은 빠른 경로 제외다. 질환·기록·내일·근거 요청 등 추가 조건은 fullmatch에 실패해 기존 경로를 탄다. DB 읽기 실패 및 설정 off도 기존 fallback이다. 읽기 전용 경로에 propose/write tool을 노출하지 않는다.

기존 FIRST_COACHING_MODE 설정은 그대로이며 `off`로 직접 연결을 비활성화할 수 있다. 프롬프트 텍스트나 승인된 릴리스 조합은 수정하지 않았다. [기존 직접 연결 실험](../first_coaching/README.md)의 작은 표본 한계를 유지하며 이번 문구 확대의 품질 통계로 재해석하지 않는다.

## 채택 판단: 기존 운영 코드 유지

후보 관련129테스트는 통과했으나 전체 검사에서 과거 프롬프트 평가 승인 검증이 `Per-attempt binding changed`로 실패했다. `clarification_execution.request_spec`는 coaching_route.py를 포함한 실행 코드 해시를 입력 키에 묶는다. 즉 기존 품질 증거를 새 라우팅 코드의 승인 증거로 재사용할 수 없다. 이를 허용하도록 검증 기준/해시를 바꾸지 않았고, 원본 답변·평가·서명도 변경하지 않았다.

후보 구현과 테스트는 [검토용 패치](natural-recommendation-candidate.patch)에 보존하고 실제 실행 파일은 원래대로 복원했다. 신규 기능을 배포했다고 주장하지 않는다. 기존 배포의 `점심 추천해줘` 직접 meal 경로는 유지된다. 향후 채택에는 후보 코드에 연결된 동결100건/조건 품질·지연·비용 비교와 별도 코드 호환성 승인 절차가 필요하다. 이번에는 새 유료100건 비교를 실행하지 않았다.

환경 실패도 구분했다: 기본 임시 폴더 WinError5, 첫 상대 basetemp 부모 부재 WinError3는 D:/AX/diet_agent/tmp 아래 실제 존재하는 부모의 절대 basetemp로 해결했다. 이 환경 오류와 승인 해시 불일치는 별개다. [pytest 임시 폴더 공식 설명](https://docs.pytest.org/en/stable/how-to/tmp_path.html).
